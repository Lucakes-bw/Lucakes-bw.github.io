# dkv：一个用来学习的分布式键值存储

《分布式系统》专栏的代码，C11。第一章「分布式基础」用到的是一个带主从复制的内存键值服务器，以及几个故意制造故障的工具。文章中的输出都来自这些程序：Docker 中的 4 个 Ubuntu 24.04 容器（n1、n2、n3 是节点，c1 是客户端），内核 6.8，GCC 13.3；虚拟机 2 核、2 GB 内存。延迟、丢包和网络分区用 `tc netem` 和 `iptables` 制造。

```bash
make
# 节点：n1 为主，复制到 n2、n3；-acks 是写入要等几个从节点确认（0 为异步）
./build/kvd -id n1 -role primary -peers 10.77.0.12:7000,10.77.0.13:7000 -acks 1 -fence 1
./build/kvd -id n2 -role backup  -peers 10.77.0.11:7000,10.77.0.13:7000 -acks 1 -fence 1 -auto 1000 -watch 10.77.0.11:7000
# 客户端
./build/cli lat 10.77.0.11:7000 5000                 # 延迟分布
./build/cli incr 10.77.0.11:7000 2000 100 1 7        # 超时重试 + 去重
./build/cli seq 10.77.0.11:7000 a 6 /tmp/a.txt       # 不停地写，记下确认过的写入
./build/cli check 10.77.0.12:7000 /tmp/a.txt         # 确认过的写入还剩多少
./build/cli quorum 2 2 10 n1:7000 n2:7000 n3:7000    # 法定人数读写
./build/cli lww 1000 5000 wall n1:7000 n2:7000 n3:7000   # 时钟偏差与最后写入者胜
./build/hb 10.77.0.11:7000 100 500 60                # 心跳故障检测
```

| 文件 | 内容 |
|---|---|
| `kvd.c` | 节点：内存哈希表；主节点把每次写入追加到复制日志，每个从节点一个复制线程；`-acks` 同步/异步复制，`-fence` 任期检查，`-dedup` 请求去重，`-auto` 心跳超时后自动晋升 |
| `cli.c` | 客户端与压测：`lat`、`incr`、`seq`、`check`、`diff`、`quorum`、`lww` |
| `hb.c` | 基于 UDP 心跳的故障检测器，打印每次怀疑和误判 |
| `net.c`、`net.h` | TCP 连接、按行读写、计时 |

这一章的 kvd **故意是不安全的**：故障转移不经过投票，晋升的从节点不一定拥有最新的数据，日志冲突时状态不回滚。文章用它测出这些问题，下一章用 Raft 解决。

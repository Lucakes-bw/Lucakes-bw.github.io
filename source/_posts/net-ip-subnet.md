> **本文目标**：理解 IPv4 地址的结构；会计算子网掩码、网络地址、广播地址和可用的主机数；理解主机怎样判断目的地址是否在同一个子网；认识特殊地址和私有地址；了解 NAT 和 IPv6。
>
> **前置知识**：上一篇的实验网络（3 台主机连在一台交换机上）、ARP。
>
> **实验环境**：Ubuntu 24.04 容器，iproute2 6.1。

## 1. IPv4 地址

IPv4 地址是一个 32 位的整数，通常写成 4 个 0～255 的十进制数，用点隔开（**点分十进制**），每个数对应 8 位：

```
192.168.1.130  =  11000000 10101000 00000001 10000010
```

MAC 地址只能在同一个网络内使用，IP 地址则要能在全世界范围内找到一台主机。全世界有几十亿台设备，路由器不可能记住每一个地址的位置。办法和电话号码一样：**分区**。IP 地址分成两部分：

- **网络部分**：标识主机所在的网络，类似区号；
- **主机部分**：标识网络中的某一台主机，类似号码。

路由器只需要记住「去某个网络往哪里走」，到了那个网络，再由那里的交换机和 ARP 找到具体的主机。

## 2. 子网掩码和 CIDR

网络部分有多少位，由**子网掩码**决定。上一篇实验网络中 h1 的地址：

```bash
ip netns exec h1 ip -4 addr show eth0 | grep inet
```

```
    inet 10.0.0.1/24 scope global eth0
```

`/24` 表示前 24 位是网络部分，后 8 位是主机部分。这种写法叫 **CIDR**（无类别域间路由）记法。写成掩码就是网络部分全 1、主机部分全 0：`255.255.255.0`。

由地址和前缀长度可以算出：

| 名称 | 算法 | 10.0.0.1/24 |
|---|---|---|
| 子网掩码 | 前 n 位为 1 | 255.255.255.0 |
| 网络地址 | 地址 AND 掩码（主机部分全 0） | 10.0.0.0 |
| 广播地址 | 主机部分全 1 | 10.0.0.255 |
| 可用主机 | 网络地址和广播地址之间 | 10.0.0.1 ～ 10.0.0.254，共 254 个 |

主机部分有 h 位，就有 2ʰ 个地址，减去网络地址和广播地址，可用 2ʰ − 2 个。前缀不一定是 8 的倍数，这时要换算成二进制才看得清楚。下面的演示可以输入任意的地址，逐位查看计算过程，默认的例子是 192.168.1.130/26：

几个例子（用 Python 的 `ipaddress` 模块验证过，结果和演示一致）：

| 地址 | 掩码 | 网络地址 | 广播地址 | 可用主机 | 主机数 |
|---|---|---|---|---|---|
| 192.168.1.130/26 | 255.255.255.192 | 192.168.1.128 | 192.168.1.191 | .129 ～ .190 | 62 |
| 10.20.30.40/20 | 255.255.240.0 | 10.20.16.0 | 10.20.31.255 | 10.20.16.1 ～ 10.20.31.254 | 4094 |
| 172.17.0.3/16 | 255.255.0.0 | 172.17.0.0 | 172.17.255.255 | 172.17.0.1 ～ 172.17.255.254 | 65534 |
| 192.168.1.5/30 | 255.255.255.252 | 192.168.1.4 | 192.168.1.7 | .5 ～ .6 | 2 |

最后一行的 /30 只有 2 个可用地址，常用于两台路由器之间的连接。172.17.0.3/16 是本专栏实验容器自己的地址：Docker 默认的网络是 172.17.0.0/16。

> 早期的 IP 地址按第一个数分成 A 类（/8）、B 类（/16）、C 类（/24），前缀长度是固定的，浪费严重：一个只需要 300 个地址的单位，要么用 C 类不够，要么用 B 类浪费 6 万多个。CIDR 允许任意长度的前缀，这种分类已经废弃，但「C 类地址」这样的说法还经常听到。

## 3. 同一个子网才能直接通信

主机发送一个 IP 数据报时，先判断目的地址和自己是不是在**同一个子网**：用自己的掩码分别和两个地址做 AND，网络地址相同，就是同一个子网，直接用 ARP 找对方的 MAC，把帧交给交换机；否则就要交给**路由器**（下一篇）。这个判断体现在路由表中：

```bash
ip netns exec h1 ip route
```

```
10.0.0.0/24 dev eth0 proto kernel scope link src 10.0.0.1
```

配置地址时，内核自动加上了这一条：「10.0.0.0/24 这个网络直接在 eth0 上」。h1 没有其他的路由。

### 3.1 换到另一个子网

把 h3 的地址改成 10.0.1.3/24。它仍然插在同一台交换机上，物理上和 h1 完全连通：

```bash
ip netns exec h3 ip addr flush dev eth0
ip netns exec h3 ip addr add 10.0.1.3/24 dev eth0
ip netns exec h1 ping -c 1 10.0.1.3
ip netns exec h3 ping -c 1 10.0.0.1
```

```
ping: connect: Network is unreachable
ping: connect: Network is unreachable
```

两个方向都不通，而且错误是 `Network is unreachable`：10.0.1.3 不在 h1 的 10.0.0.0/24 中，h1 的路由表中又没有其他路由，所以内核根本不知道该把包交给谁，连 ARP 请求都没有发出。

把两边的掩码都改成 /16，它们就又在同一个子网 10.0.0.0/16 中了：

```bash
ip netns exec h1 ip addr flush dev eth0; ip netns exec h1 ip addr add 10.0.0.1/16 dev eth0
ip netns exec h3 ip addr flush dev eth0; ip netns exec h3 ip addr add 10.0.1.3/16 dev eth0
ip netns exec h1 ip route
ip netns exec h1 ping -c 1 10.0.1.3
```

```
10.0.0.0/16 dev eth0 proto kernel scope link src 10.0.0.1
64 bytes from 10.0.1.3: icmp_seq=1 ttl=64 time=0.034 ms
```

### 3.2 只改一边

如果 h1 是 /16，h3 仍是 10.0.1.3/24 呢？h1 认为 10.0.1.3 和自己在同一个子网，h3 却不这么认为。h1 ping h3，在 h3 上抓包：

```
07:10:43.950109 ARP, Request who-has 10.0.1.3 tell 10.0.0.1, length 28
07:10:45.014755 ARP, Request who-has 10.0.1.3 tell 10.0.0.1, length 28
```

h1 发出了 ARP 请求，h3 也收到了，**但它没有回答**。Linux 在回答 ARP 请求前会检查能否回到发问的地址，而在 h3 看来，10.0.0.1 不在自己的子网中，又没有其他路由可以到达，于是忽略了这个请求。

**掩码配置错误**是网络故障的常见原因，而且像这里一样，表现出来的症状（「ARP 发了没人回」）和原因（掩码）之间看不出联系。排查时先用 `ip addr` 和 `ip route` 检查两边的配置是否一致。

（实验后把 h1、h3 的地址恢复成了 10.0.0.1/24 和 10.0.0.3/24。）

## 4. 特殊地址

| 地址 | 含义 |
|---|---|
| `0.0.0.0` | 「本机的任意地址」或「未知地址」：服务器监听 `0.0.0.0` 表示在所有网卡上接受连接；`0.0.0.0/0` 表示所有地址（默认路由） |
| `127.0.0.0/8` | **回环地址**，发往它的数据不离开本机。不只是 127.0.0.1，整个 /8 都是 |
| `255.255.255.255` | 受限广播，只在本网络内 |
| 子网的广播地址 | 如 10.0.0.255，发往子网中的所有主机 |
| `169.254.0.0/16` | 链路本地地址：没有 DHCP 服务器分配地址时，主机自己选一个 |
| `224.0.0.0/4` | 组播地址 |

整个 `127.0.0.0/8` 都是回环地址：

```bash
ip netns exec h1 ping -c 1 127.0.0.5
```

```
64 bytes from 127.0.0.5: icmp_seq=1 ttl=64 time=0.065 ms
```

ping 子网的广播地址呢？

```bash
ip netns exec h1 ping -c 2 -b 10.0.0.255
```

```
WARNING: pinging broadcast address
PING 10.0.0.255 (10.0.0.255) 56(84) bytes of data.

--- 10.0.0.255 ping statistics ---
2 packets transmitted, 0 received, 100% packet loss, time 1037ms
```

没有任何主机回答。`/proc/sys/net/ipv4/icmp_echo_ignore_broadcasts` 的值是 1：Linux 默认忽略发往广播地址的 ping。否则攻击者可以用伪造的源地址 ping 一个大网络的广播地址，让所有主机同时回复受害者（这种攻击叫 Smurf 攻击）。

## 5. 私有地址和 NAT

IPv4 只有约 43 亿个地址，早已不够分配。为此，下面三段地址被保留为**私有地址**，任何单位都可以在内部使用，但它们不能出现在互联网上：

| 范围 | CIDR | 地址数 |
|---|---|---|
| 10.0.0.0 ～ 10.255.255.255 | 10.0.0.0/8 | 约 1677 万 |
| 172.16.0.0 ～ 172.31.255.255 | 172.16.0.0/12 | 约 105 万 |
| 192.168.0.0 ～ 192.168.255.255 | 192.168.0.0/16 | 约 6.5 万 |

家里的路由器分配的 192.168.x.x、实验网络的 10.0.0.x、Docker 的 172.17.0.x，都是私有地址。

使用私有地址的主机怎样访问互联网？上一篇抓到的包中，源地址是 172.17.0.3，example.com 的服务器不可能把响应发回这个地址。答案是 **NAT**（网络地址转换）：出口的路由器把发出的包的源地址换成自己的公网地址（同时记录下这个对应关系），响应回来时再换回去。于是一个家庭、一个公司的所有设备可以共用一个公网地址。下一篇会在实验网络中配置一个 NAT 路由器，抓包看地址是怎样被替换的。

NAT 缓解了地址不足的问题，但也破坏了「每台主机都有唯一地址」的设计：外面的主机无法主动连接 NAT 后面的主机。这也是为什么家里的电脑不能直接作为服务器被外网访问。

## 6. IPv6

**IPv6** 地址有 128 位，数量是 2¹²⁸，几乎用不完，从根本上解决了地址不足的问题。它写成 8 组 16 位的十六进制数，用冒号分隔，连续的 0 可以用 `::` 省略一次。上一篇的实验中，抓包时能看到很多 IPv6 的包，看一下 h2 的 IPv6 地址：

```bash
ip netns exec h2 ip -6 addr show eth0 | grep inet6
ip netns exec h2 ip link show eth0 | grep ether
```

```
    inet6 fe80::ff:fe00:2/64 scope link
    link/ether 02:00:00:00:00:02 brd ff:ff:ff:ff:ff:ff link-netnsid 0
```

我们并没有给 h2 配置 IPv6 地址，它自动生成了一个**链路本地地址** `fe80::ff:fe00:2`（只在本链路内有效，相当于 IPv4 的 169.254.x.x）。这个地址由 MAC 地址生成：MAC `02:00:00:00:00:02` 的中间插入 `ff:fe`，并把第一个字节的第 7 位取反（`02` 变成 `00`），得到 `0000:00ff:fe00:0002`，前面加上 `fe80::`，省略 0 之后就是 `fe80::ff:fe00:2`。

IPv6 还有其他改进：没有广播（用组播代替，上一篇抓到的 `ff02::16` 等就是组播地址），不再需要 ARP（用 ICMPv6 的邻居发现代替，抓到的 `neighbor solicitation` 就是它），路由器也不再分片。IPv6 和 IPv4 不兼容，两者将长期共存。本专栏的实验以 IPv4 为主。

## 7. 常见错误

1. **把网络地址或广播地址分配给主机**：10.0.0.0/24 中的 .0 和 .255 不能用（/31 和 /32 除外）。
2. **两台主机的掩码不一致**：一方认为在同一个子网，另一方不认为，出现单向不通或者 ARP 没有回答的怪现象。
3. **以为只有 127.0.0.1 是回环地址**：整个 127.0.0.0/8 都是。
4. **以为插在同一台交换机上就能通信**：还要在同一个子网中（或者有路由）。
5. **把私有地址当作公网地址**：10.x、172.16～31.x、192.168.x 在互联网上不可达。
6. **用 `ping 广播地址` 发现主机**：Linux 默认不回应。

## 8. 小结

- IPv4 地址 32 位，分为网络部分和主机部分，前缀长度（/n）或子网掩码决定分界线
- 网络地址 = 地址 AND 掩码；广播地址 = 主机部分全 1；可用主机数 = 2ʰ − 2
- 发送前先判断目的地址是否在同一个子网：是就直接 ARP，否就交给路由器；实测换到另一个子网后报 `Network is unreachable`，只改一边的掩码时 ARP 没有回答
- 特殊地址：0.0.0.0、127.0.0.0/8（回环）、广播地址、169.254.0.0/16（链路本地）
- 私有地址 10/8、172.16/12、192.168/16 只能在内部使用，访问互联网要经过 NAT
- IPv6 地址 128 位；链路本地地址 fe80:: 可以由 MAC 地址生成


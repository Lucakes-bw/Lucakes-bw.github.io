## 2. 用什么表示一条路线

`route.h` 定义了路线的结构：

```c
typedef struct {
    int* stations;      // stations[0] 是起点，stations[n-1] 是终点
    int* lines;         // lines[i]（i >= 1）：从 stations[i-1] 到 stations[i] 坐的线路；lines[0] 不使用
    int n;              // 车站的个数，坐了 n-1 站
} Route;
```

比如上面「北站 → 南站」的路线，在 `Route` 中是这样的：

```
i           0     1      2      3       4     5      6
stations    北站  体育馆  文化宫  人民广场  南湖  大学城  南站
lines       -     2号线  2号线  2号线    2号线  2号线  2号线
```

`lines[i]` 记录的是**到达第 i 站时坐的那条线路**，所以 `lines[0]` 没有意义。为什么每一段都要记线路，而不是只记车站？因为同一对相邻的车站之间可能不止一条线路（里程碑 1 的思考题 3），只看车站，就不知道是坐哪条线到的，也就算不出换乘。

找到路线时，`routeFewestStops` 用 `malloc` 分配两个数组，填好 `*r`，返回 0；`main.c` 输出以后会调用 `routeFree` 释放（`routeFree` 已经写好了）。不连通时返回 -1，不分配内存。

`main.c` 输出之前会检查你给的路线：起点和终点对不对，每一段的两个车站是不是真的在那条线路上相邻。有问题时会告诉你，而不是输出一条错误的路线：

```
路线有误：应该从 西山 到 港口，实际是从 港口 到 西山
路线有误：果园 和 体育馆 在 1号线 上不相邻
```

## 3. BFS 为什么能找到站数最少的路线

### 3.1 一层一层地扩展

每坐一站，就是在图中走一条边。所以「坐的站数最少」就是「经过的边最少」，这正是《图的表示与遍历》中 BFS 解决的问题：在边没有权重（或者说所有边的权重都是 1）的图中，求最短路径。

BFS 从起点出发，先访问离起点 1 站的所有车站，再访问离起点 2 站的所有车站……用一个**队列**保证这个顺序：先发现的先处理。一个车站第一次被发现时，它离起点的站数就确定了，以后不可能再找到更短的路线到它：更短的路线上的车站都在更早的层中，早就处理完了。

所以 BFS 只需要在**第一次发现**一个车站时记下两件事：

- `prev[v]`：从哪个车站过来的（前驱）；
- `via[v]`：坐的哪条线路。

到终点被发现时，从终点沿着 `prev` 一步一步往回走，就能还原整条路线。

### 3.2 站数相同的路线不止一条，BFS 会选哪一条？

[项目总览](/posts/ds-project-metro/)中说过，从西山到港口，坐 7 站的走法有好几种。BFS 只会给出其中一条。是哪一条，取决于**发现的顺序**：

- 队列先进先出，所以同一层的车站按发现的顺序处理；
- 处理一个车站时，按邻接表的顺序看它的相邻车站；
- 一个车站被谁**第一个**发现，谁就是它的前驱，以后不再改。

邻接表的顺序在里程碑 1 中已经确定了（按读取数据的顺序追加），所以只要按上面的规则写，结果就是唯一确定的。测试也是按这个规则生成的。**不要**从终点开始反向 BFS，也不要倒着遍历邻接表，那样得到的同样是站数最少的路线，但可能是另一条，测试会失败。

这也解释了一个看起来奇怪的现象：反过来走，路线可能不一样。

```
metro> stops 西山 港口
西山 → 港口：坐 7 站，换乘 1 次，用时 23 分钟（乘车 18 分钟，换乘 5 分钟）
  1号线：西山 → 东门，5 站，13 分钟
  4号线：东门 → 港口，2 站，5 分钟
metro> stops 港口 西山
港口 → 西山：坐 7 站，换乘 2 次，用时 29 分钟（乘车 19 分钟，换乘 10 分钟）
  4号线：港口 → 东湖，1 站，2 分钟
  3号线：东湖 → 市政府，2 站，7 分钟
  1号线：市政府 → 西山，4 站，10 分钟
```

两条都是 7 站，都是正确答案。从港口出发时，港口的邻接表中只有东湖，东湖的邻接表中 3 号线的会展中心排在 4 号线的东门前面，所以会展中心先被发现，3 号线的这条路就「抢先」到达了市政府。

BFS 完全不关心换乘。它甚至会给出这样的路线：

```
metro> stops 港口 植物园
港口 → 植物园：坐 7 站，换乘 3 次，用时 34 分钟（乘车 19 分钟，换乘 15 分钟）
  4号线：港口 → 东湖，1 站，2 分钟
  3号线：东湖 → 市政府，2 站，7 分钟
  1号线：市政府 → 果园，3 站，7 分钟
  3号线：果园 → 植物园，1 站，3 分钟
```

先坐 3 号线，换到 1 号线，又换回 3 号线。实际上在东湖换上 3 号线，一直坐到植物园，也是 7 站，只要换乘一次。对 BFS 来说，这两条路线都是 7 条边，没有区别。要让换乘也参与比较，就得把换乘放进图里，这是下一个里程碑的内容。

### 4.1 需要的数组

```c
int n = m->nstations;
int* prev = malloc(sizeof(int) * n);    // prev[v]：v 的上一站，-1 表示还没有发现
int* via = malloc(sizeof(int) * n);     // via[v]：从上一站到 v 坐的线路
int* queue = malloc(sizeof(int) * n);
```

不需要单独的 `visited` 数组：`prev[v] >= 0` 就表示 v 已经发现过了。起点没有上一站，把 `prev[from]` 设为 `from` 自己，这样它也被标记为「已经发现」。

队列直接用一个长度为 n 的数组和两个下标 `head`、`tail`。每个车站最多入队一次，`tail` 不会超过 n，所以不需要《队列》一文中的循环队列，也不需要扩容。

### 4.2 BFS

```c
for (int i = 0; i < n; ++i) prev[i] = -1;
prev[from] = from;
int head = 0, tail = 0;
queue[tail++] = from;
while (head < tail && prev[to] < 0) {
    int u = queue[head++];
    // 遍历 u 的邻接表：每个还没有发现的相邻车站 e->to，
    // 记下 prev 和 via，放进队尾
}
```

循环的条件中加了 `prev[to] < 0`：终点一旦被发现，路线就确定了，不用再继续。注意它是在处理完一整个车站以后才检查的，这和把整张图都 BFS 完的结果完全相同（终点的前驱在第一次发现时就定下了，后面不会再改），只是少做了一些无用功。

<details>
<summary>提示：为什么要在入队时标记，而不是出队时</summary>

如果出队时才设置 `prev`，一个车站在出队之前可能被好几个车站发现，入队好几次。这有两个问题：

1. 队列的长度可能超过 n，`queue[tail++]` 会越界，AddressSanitizer 会报告 `heap-buffer-overflow`；
2. 前驱被后来的车站覆盖，结果不再是「第一个发现它的车站」，和测试期望的路线不同。

</details>

### 4.3 还原路线

终点被发现以后，从 `to` 沿着 `prev` 往回走，直到 `from`，得到的是**倒序**的路线。可以先走一遍数出车站的个数，分配好数组，再走一遍从数组末尾往前填：

```c
int count = 1;
for (int v = to; v != from; v = prev[v]) ++count;
// 分配 r->stations 和 r->lines，长度都是 count
// 再从 v = to、i = count - 1 开始往回走：
//     r->stations[i] = v;   i > 0 时 r->lines[i] = via[v]
```

这样不需要先存到一个临时数组里再反转。最后设置 `r->n = count`，`r->lines[0]` 可以随便填一个值，比如 -1。

<details>
<summary>提示：一个通用的「还原路线」函数</summary>

里程碑 3、4 还要还原路线，但它们的前驱数组和这里不一样，所以这个函数不一定能复用。参考实现中它是这样的：

```c
// 用前驱数组还原路线：prev[v] 是 v 的上一站，via[v] 是从上一站到 v 坐的线路
static void buildRoute(int from, int to, const int* prev, const int* via, Route* r)
{
    int n = 1;
    for (int v = to; v != from; v = prev[v]) ++n;
    r->stations = xmalloc(sizeof(int) * n);
    r->lines = xmalloc(sizeof(int) * n);
    r->n = n;
    r->lines[0] = -1;
    for (int v = to, i = n - 1; i >= 0; v = prev[v], --i) {
        r->stations[i] = v;
        if (i > 0) r->lines[i] = via[v];
    }
}
```

`xmalloc` 是参考实现中自己写的一个小函数：调用 `malloc`，失败时直接 `exit(1)`。

</details>

## 6. 常见错误

1. **出队时才标记已经发现**。见 4.2 节的提示：队列越界，或者前驱被覆盖。
2. **路线是倒着的**。从终点往回走得到的是倒序，直接按这个顺序填进数组，`main.c` 会报告「路线有误：应该从 西山 到 港口，实际是从 港口 到 西山」。
3. **`lines` 错了一位**。`lines[i]` 是到达第 i 站时坐的线路，也就是 `via[stations[i]]`，不是 `via[stations[i-1]]`。错了一位时，`main.c` 会报告某两站「在某条线上不相邻」。
4. **找不到路线时没有释放内存**，或者返回了 -1 却又分配了 `r` 中的数组。
5. **把 `prev[from]` 设成了 -1**。起点会被当成「还没有发现」，处理它的相邻车站时，起点又被放进队列一次。这样队列中最多会有 n + 1 个元素，`queue[tail++]` 可能越界。

## 7. 思考题

1. **双向 BFS**：同时从起点和终点出发 BFS，两边相遇时停下。它为什么通常比单向 BFS 快？在示例城这么小的图上，能快多少？
2. 如果要在**站数最少**的路线中，再选**换乘最少**的那一条，只靠 BFS 能做到吗？
3. 如果要列出**所有**站数最少的路线，`prev` 需要怎么改？

<details>
<summary>点击查看答案</summary>

1. BFS 访问的车站数大致随层数增长。如果每个车站平均有 b 个新的相邻车站，从起点 BFS 到 d 层大约要访问 b^d 个车站；双向 BFS 两边各走 d/2 层，一共大约 2·b^(d/2) 个，指数减半了。地铁图很稀疏，b 只比 1 大一点，所以在示例城上几乎看不出区别；在社交网络这种 b 很大的图上，差别非常明显。

2. 可以。BFS 先求出每个车站离起点的站数 `dist`，只保留满足 `dist[v] = dist[u] + 1` 的边 u → v，这些边组成一张有向无环图，所有站数最少的路线都在这张图中。在这张图上再按层做一次动态规划，状态是（车站，到达时坐的线路），就能求出换乘最少的那一条。不过「到达时坐的线路」这个想法本身，就是里程碑 3 的核心。

3. 把 `prev[v]` 从一个数改成一个列表：所有满足 `dist[u] + 1 = dist[v]` 的 u 都是 v 的前驱。还原时从终点开始做 DFS，列出所有路径。路线的条数可能是指数级的（想一想棋盘上从一角到对角有多少条最短路线），所以只适合在小图上这样做。

</details>

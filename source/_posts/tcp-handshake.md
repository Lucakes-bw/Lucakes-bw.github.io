## 1. TCP 的特点

TCP（Transmission Control Protocol）是**面向连接**、**可靠**、**基于字节流**的传输层协议。通信之前必须先建立连接，通信结束后要断开连接。

## 2. 三次握手

```
客户端                                  服务器
  |                                       | LISTEN
  | ---- SYN, seq=x ------------------->  |
  | SYN_SENT                              | SYN_RCVD
  | <--- SYN+ACK, seq=y, ack=x+1 -------  |
  | ESTABLISHED                           |
  | ---- ACK, ack=y+1 ----------------->  |
  |                                       | ESTABLISHED
```

1. 客户端发送 `SYN`，携带自己的初始序号 `x`
2. 服务器回复 `SYN+ACK`，确认 `x+1`，并携带自己的初始序号 `y`
3. 客户端回复 `ACK`，确认 `y+1`，连接建立

**为什么是三次？** 双方都要确认「自己能发、对方能收」。两次握手时，服务器无法确认客户端收到了自己的序号；同时，三次握手还能防止已失效的旧 `SYN` 请求导致错误连接。

## 3. 四次挥手

```
客户端                                  服务器
  | ---- FIN -------------------------->  |
  | FIN_WAIT_1                            | CLOSE_WAIT
  | <--- ACK ---------------------------  |
  | FIN_WAIT_2                            |   （服务器可能还有数据要发）
  | <--- FIN ---------------------------  |
  | TIME_WAIT                             | LAST_ACK
  | ---- ACK -------------------------->  |
  |  等待 2MSL 后关闭                      | CLOSED
```

**为什么是四次？** TCP 是全双工的，每个方向需要单独关闭。服务器收到 `FIN` 时可能还有数据没发完，所以 `ACK` 和 `FIN` 通常分两次发送。

## 4. TIME_WAIT 的作用

主动关闭方会在 `TIME_WAIT` 状态等待 2MSL（报文最大生存时间的两倍）：

- 保证最后一个 `ACK` 能到达对方；如果丢失，对方会重发 `FIN`
- 让本连接的旧报文在网络中全部消失，避免影响相同端口的新连接

## 5. 小结

| 过程 | 次数 | 关键点 |
| --- | --- | --- |
| 建立连接 | 3 次 | 同步双方初始序号 |
| 断开连接 | 4 次 | 全双工，两个方向分别关闭 |

> **本文目标**：理解分治思想；掌握快速排序的划分过程，理解它的最坏情况和改进方法；掌握归并排序和合并过程；能比较两者的优缺点。
>
> **前置知识**：《简单排序》，C 语言的《函数》（递归和栈溢出）。

## 1. 分治

O(n²) 的排序，问题在于每次比较只能带来很少的信息。**分治**（divide and conquer）的思路是：把问题分成几个规模更小的同类问题，分别解决，再把结果合起来。

- **快速排序**：先**划分**，再递归。选一个基准，把比它小的放左边、大的放右边，然后分别排序左右两部分。合起来时什么都不用做。
- **归并排序**：先递归，再**合并**。把数组一分为二，分别排序，然后把两个有序的部分合并成一个。分的时候什么都不用做。

如果每次都能对半分，一共有 log n 层，每层的工作量是 O(n)，总共就是 **O(n log n)**。

## 2. 快速排序

### 2.1 划分

快速排序的核心是**划分**（partition）：选一个元素作为**基准**（pivot），重新排列区间，使得基准左边的都比它小，右边的都不比它小。划分之后，**基准就在它最终的位置上了**。下面是最容易理解的 Lomuto 划分，以区间最后一个元素为基准：

```c
static int partitionLomuto(int* a, int lo, int hi)
{
    int pivot = a[hi];
    int i = lo;                                 // a[lo..i-1] 都小于 pivot
    for (int j = lo; j < hi; ++j) {
        if (a[j] < pivot) swap(&a[i++], &a[j]);
    }
    swap(&a[i], &a[hi]);                        // 基准放到最终位置
    return i;
}

void quickSortNaive(int* a, int lo, int hi)
{
    if (lo >= hi) return;
    int p = partitionLomuto(a, lo, hi);
    quickSortNaive(a, lo, p - 1);               // 左边都比基准小
    quickSortNaive(a, p + 1, hi);               // 右边都不比基准小
}
```

`j` 从左到右扫描，`i` 指向「下一个小于基准的元素应该放的位置」。扫描结束后，把基准和 `a[i]` 交换。在演示中观察每一次划分，然后输入已经有序的 `1 2 3 4 5 6 7 8`，对比比较次数和递归深度：

### 2.2 最坏情况

演示中对随机的 8 个数只比较了 16 次，递归深度 5；而对有序的 8 个数，比较了 28 次（= 8 × 7 / 2），递归深度 8。原因是：以最后一个元素为基准，对于已经有序的数组，基准**每次都是最大的**，划分之后左边有 n - 1 个元素，右边一个都没有。每次只减少一个元素，递归深度是 n，比较次数是 n(n-1)/2，**退化成了 O(n²)**。

实测朴素快速排序处理有序数据（`-O2`）：

```
朴素快排，有序数据 n = 10000     11.8 ms，递归深度 9999
朴素快排，有序数据 n = 20000     46.7 ms，递归深度 19999
朴素快排，有序数据 n = 40000    187.0 ms，递归深度 39999
```

n 每翻一倍，时间变成 4 倍，递归深度始终等于 n。处理 20 万个有序元素时（`-O0` 编译），递归太深，程序直接**栈溢出**崩溃了（退出码 139，见《函数》第 3.2 节）。用 `-O2` 编译时，编译器把第二个递归调用优化成了循环，没有立即崩溃，但 100 万个有序元素需要比较约 5000 亿次，按上面的数据推算要将近 2 分钟。

已经有序或基本有序的数据在实际中非常常见，所以朴素的快速排序不能直接使用。

### 2.3 改进

```c
static int medianOfThree(int* a, int lo, int hi)
{
    int mid = lo + (hi - lo) / 2;
    if (a[mid] < a[lo]) swap(&a[mid], &a[lo]);
    if (a[hi] < a[lo]) swap(&a[hi], &a[lo]);
    if (a[hi] < a[mid]) swap(&a[hi], &a[mid]);
    return a[mid];                              // 头、中、尾三个数的中位数
}

void quickSort(int* a, int lo, int hi)
{
    while (hi - lo > 16) {
        int pivot = medianOfThree(a, lo, hi);
        int i = lo - 1, j = hi + 1;             // Hoare 划分：两个指针从两端向中间扫描
        for (;;) {
            do ++i; while (a[i] < pivot);
            do --j; while (a[j] > pivot);
            if (i >= j) break;
            swap(&a[i], &a[j]);
        }
        if (j - lo < hi - j) {                  // 先递归处理较短的一半，较长的一半用循环
            quickSort(a, lo, j);
            lo = j + 1;
        } else {
            quickSort(a, j + 1, hi);
            hi = j;
        }
    }
    insertionSort(a, lo, hi);                   // 小区间用插入排序
}
```

（`insertionSort(a, lo, hi)` 是上一篇的插入排序，改为对区间 `[lo, hi]` 排序。）

四个改进：

1. **三数取中**：取头、中、尾三个数的中位数作为基准。对于有序的数据，中位数正好在中间，划分是平衡的。
2. **Hoare 划分**：两个指针从两端向中间扫描，左边遇到不小于基准的停下，右边遇到不大于基准的停下，交换。它的交换次数比 Lomuto 少；更重要的是，遇到**大量重复的元素**时，Lomuto 划分会把它们全部分到一边，退化成 O(n²)，而 Hoare 划分会把相等的元素平均地分到两边。
3. **小区间用插入排序**：区间小于 16 个元素时，递归的开销比排序本身还大，上一篇讲过，插入排序在小数据上最快。
4. **只对较短的一半递归**：较长的一半用循环处理。这样递归深度最多是 log n，不会栈溢出。

### 2.4 实测

```
n = 1000000，随机数据：
  朴素快排      65.3 ms，递归深度 49 
  改进快排      40.9 ms，递归深度 11 
  归并排序      39.1 ms 
  标准库 qsort  55.1 ms 
n = 1000000，有序数据：
  改进快排       4.0 ms，递归深度 16 
  归并排序      18.8 ms 
  标准库 qsort   1.3 ms 
n = 1000000，全部相同数据：
  改进快排       4.5 ms，递归深度 16 
  归并排序       8.9 ms 
  标准库 qsort   0.8 ms 
```

（朴素快排在有序和全部相同的数据上太慢，没有参加这两项测试。所有结果都检查过确实排好了序。）

- 在随机数据上，改进后的快速排序比朴素版本快了 37%，递归深度从 49 降到了 11。
- 在有序和全部相同的数据上，改进版只用了 4 毫秒左右，没有任何退化。
- 改进版在随机数据上比 `qsort` 还快，部分原因是 `qsort` 是通用的，每次比较都要通过函数指针调用比较函数，而我们的代码直接比较 `int`。`qsort` 在有序和全部相同的数据上特别快，这台机器的标准库实现很可能对这些情况做了专门的处理。

即使有这些改进，快速排序的最坏情况在理论上仍然是 O(n²)（可以构造出让三数取中失效的输入）。C++ 的 `std::sort` 使用**内省排序**（introsort）：先用快速排序，如果递归深度超过 2 log n，就改用堆排序，保证最坏 O(n log n)；小区间用插入排序。

## 3. 归并排序

```c
static void merge(int* a, int* tmp, int lo, int mid, int hi)
{
    int i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi) {
        tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];   // <=：相等时取左边的，保证稳定
    }
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= hi) tmp[k++] = a[j++];
    memcpy(a + lo, tmp + lo, (hi - lo + 1) * sizeof(int));
}

static void mergeSortRec(int* a, int* tmp, int lo, int hi)
{
    if (lo >= hi) return;
    int mid = lo + (hi - lo) / 2;
    mergeSortRec(a, tmp, lo, mid);              // 分别排好左右两半
    mergeSortRec(a, tmp, mid + 1, hi);
    merge(a, tmp, lo, mid, hi);                 // 合并两个有序的部分
}

void mergeSort(int* a, int n)
{
    int* tmp = malloc(n * sizeof(int));         // O(n) 的额外空间
    if (tmp == NULL) exit(1);
    mergeSortRec(a, tmp, 0, n - 1);
    free(tmp);
}
```

**合并**两个有序的部分很简单：用两个指针分别指向两部分的开头，每次取较小的一个放进结果，被取走的那一边指针后移。一边取完了，另一边剩下的直接接在后面。合并 n 个元素只需要 O(n) 的时间。

演示中，合并时为了画面清楚，直接在原数组中移动元素，效果和先放到 `tmp` 再复制回来相同：

归并排序的特点：

- **无论输入是什么，都是 O(n log n)**：每次都对半分，不存在最坏情况；
- **稳定**：合并时相等的元素取左边的（`<=`），保持原来的顺序；
- 需要 **O(n) 的额外空间**存放 `tmp`，这是它的主要缺点；
- 合并是顺序访问内存的，适合处理**链表**（不需要额外空间）和**外部排序**（数据太大，放不进内存，要分块排序后在磁盘上合并）。

C++ 的 `std::stable_sort` 和 Python 的 `sorted`（Timsort）都基于归并排序。

所有的程序都用 `-fsanitize=address,undefined` 检查过。

## 4. 快速排序和归并排序的比较

| | 快速排序（改进后） | 归并排序 |
|---|---|---|
| 平均时间 | O(n log n) | O(n log n) |
| 最坏时间 | O(n²)（很难遇到） | O(n log n) |
| 额外空间 | O(log n)（递归栈） | O(n) |
| 稳定 | 否 | 是 |
| 特点 | 原地排序，常数小，对缓存友好 | 稳定，最坏情况有保证，适合链表和外部排序 |

## 5. 常见错误

1. **固定取第一个或最后一个元素作为基准**：有序数据退化成 O(n²)，甚至栈溢出。
2. **Lomuto 划分处理大量重复元素**：同样退化。
3. **划分的边界条件写错**：死循环或者越界。快速排序是最容易写错的算法之一，写完一定要用有序、逆序、全部相同、只有一两个元素的数组测试。
4. **归并时比较条件写成 `<`**：相等时取了右边的元素，不再稳定。
5. **每次合并都 `malloc` 一个临时数组**：大量的内存分配非常慢。应该在开头分配一次，传递下去。
6. **`mid = (lo + hi) / 2`**：`lo + hi` 可能溢出，写成 `lo + (hi - lo) / 2`（第 5.4 篇二分查找中会实测）。

## 6. 小结

- 分治：快速排序先划分再递归，归并排序先递归再合并，平均都是 O(n log n)
- 划分之后基准在最终位置上；固定选端点作基准时，有序数据退化成 O(n²)，实测递归深度等于 n，20 万个元素时栈溢出
- 改进：三数取中、Hoare 划分、小区间插入排序、只递归较短的一半；实测 100 万个有序数据只需 4 毫秒
- 归并排序最坏也是 O(n log n)，稳定，但需要 O(n) 额外空间
- 实际中：`std::sort` 是快速排序 + 堆排序 + 插入排序的组合，`std::stable_sort` 基于归并排序

## 7. 练习

1. 利用快速排序的划分，不对整个数组排序，求出第 k 小的元素。它的平均复杂度是多少？
2. 修改归并排序，统计数组中逆序对的个数（i < j 且 a[i] > a[j] 的数对）。`{5, 2, 9, 1, 7, 3, 8, 4}` 有多少个逆序对？
3. 为什么快速排序在实际中通常比堆排序快，尽管两者平均都是 O(n log n)，而堆排序的最坏情况更好？

1. 划分之后，基准在位置 p。如果 p 正好等于 k，就找到了；如果 k < p，答案在左边；否则在右边。**只需要处理一边**：

   ```c
   int quickSelect(int* a, int n, int k)            // 第 k 小（从 0 开始）
   {
       int lo = 0, hi = n - 1;
       while (lo < hi) {
           swap(&a[lo + rand() % (hi - lo + 1)], &a[hi]);   // 随机选基准
           int p = partition(a, lo, hi);
           if (p == k) return a[p];
           if (k < p) hi = p - 1; else lo = p + 1;  // 只需要处理一边
       }
       return a[lo];
   }
   ```

   对 `{5, 2, 9, 1, 7, 3, 8, 4}`，k 从 0 到 7 依次得到 1 2 3 4 5 7 8 9。平均复杂度是 n + n/2 + n/4 + … = O(n)。C++ 的 `std::nth_element` 就是这个算法。这里随机选择基准，避免了有序输入导致的退化。

2. 合并时，如果右边的 `a[j]` 比左边的 `a[i]` 小，那么左边从 `i` 到 `mid` 的所有元素都比 `a[j]` 大，它们和 `a[j]` 都构成逆序对：

   ```c
   while (i <= mid && j <= hi) {
       if (a[i] <= a[j]) tmp[k++] = a[i++];
       else { tmp[k++] = a[j++]; c += mid - i + 1; }   // 左边剩下的都比 a[j] 大
   }
   ```

   结果是 13 个。正好等于上一篇演示中冒泡排序对这个数组的交换次数：冒泡排序每次交换相邻的两个元素，恰好消除一个逆序对。O(n log n) 就能数出来，而两两比较需要 O(n²)。

3. 快速排序的划分是**顺序扫描**的，访问的内存是连续的，对 CPU 缓存很友好；而堆的下沉每次跳到 2i + 1，访问位置相距越来越远，缓存命中率低。另外快速排序内层循环的操作更简单，常数更小。所以实际的排序库以快速排序为主，只在快速排序可能退化时才切换到堆排序（内省排序）。

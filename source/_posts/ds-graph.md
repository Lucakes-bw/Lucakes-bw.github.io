>
> **前置知识**：《栈》、《队列》、《二叉树与遍历》（树的 DFS 和 BFS）。

## 1. 图

线性表是一对一的关系，树是一对多的关系，而**图**描述的是**多对多**的关系：一个人有很多朋友，他的朋友又有很多朋友；一个城市有很多条道路通往其他城市。

图由**顶点**（vertex）和连接顶点的**边**（edge）组成。基本的术语：

| 术语 | 含义 |
|---|---|
| 无向图 / 有向图 | 边没有方向（朋友关系）/ 边有方向（关注关系、单行道） |
| 带权图 | 每条边有一个数值（距离、费用、时间） |
| 邻居 | 有边直接相连的两个顶点互为邻居 |
| 度 | 一个顶点的边数；有向图分为入度和出度 |
| 路径、环 | 沿着边从一个顶点走到另一个顶点；起点和终点相同的路径是环 |
| 连通 | 无向图中任意两个顶点之间都有路径 |
| 稀疏图 / 稠密图 | 边数远小于 n² / 边数接近 n²（n 是顶点数） |

树其实是一种特殊的图：连通、没有环的无向图。

## 2. 图的存储

### 2.1 邻接矩阵

用一个 n × n 的二维数组，`m[u][v] = 1` 表示 u 和 v 之间有边（带权图存权重）。无向图的矩阵是对称的。

- 判断两个顶点之间有没有边：O(1)；
- 找一个顶点的所有邻居：要扫描一整行，O(n)；
- 空间：**O(n²)**，不管有多少条边。

### 2.2 邻接表

每个顶点保存一个列表，存放它的所有邻居：

```c
typedef struct {
    int* to;                                    // 相邻顶点的编号
    int size, cap;
} AdjList;

typedef struct {
    int n;                                      // 顶点数
    AdjList* adj;                               // adj[v] 是顶点 v 的所有邻居
} Graph;

Graph graphCreate(int n)
{
    Graph g = {n, calloc(n, sizeof(AdjList))};
    if (g.adj == NULL) exit(1);
    return g;
}

static void addArc(Graph* g, int u, int v)
{
    AdjList* a = &g->adj[u];
    if (a->size == a->cap) {
        a->cap = a->cap ? a->cap * 2 : 4;
        a->to = realloc(a->to, a->cap * sizeof(int));
        if (a->to == NULL) exit(1);
    }
    a->to[a->size++] = v;
}

void addEdge(Graph* g, int u, int v)            // 无向边：两个方向各存一次
{
    addArc(g, u, v);
    addArc(g, v, u);
}

void graphFree(Graph* g)
{
    for (int i = 0; i < g->n; ++i) free(g->adj[i].to);
    free(g->adj);
}
```

每个顶点的邻居列表就是一个《顺序表》中的动态数组（也可以用链表）。

- 找一个顶点的所有邻居：O(度)；
- 判断两个顶点之间有没有边：要扫描列表，O(度)；
- 空间：**O(n + m)**，m 是边数。

### 2.3 实测

现实中的图大多是**稀疏**的：一个人的朋友数和总人数相比微不足道。建一个有 2 万个顶点、约 6 万条边的稀疏图（平均每个顶点 6 个邻居），分别用两种方式存储，从顶点 0 做一次 BFS（`-O2`）：

```
n = 20000，边数 59990
邻接矩阵 400.0 MB，BFS 检查 400000000 次，99.0 ms
邻接表   0.95 MB，BFS 检查 119980 次，0.46 ms
```

邻接矩阵要 400 MB（每个元素只用 1 个字节），而邻接表不到 1 MB，**相差 400 多倍**。BFS 时邻接矩阵要检查 4 亿个位置，邻接表只检查了 12 万次（每条边两个方向各一次）。如果有 100 万个顶点，邻接矩阵需要 1 TB，根本无法存放。

**结论：稀疏图用邻接表，稠密图或者需要频繁判断「两点之间有没有边」时用邻接矩阵。** 本章后面的算法都使用邻接表。

## 3. 深度优先搜索

**深度优先搜索**（DFS）的策略是：**沿着一条路一直走下去，走不通了再退回来，换一条路**，就像走迷宫时一只手扶着墙走。和树的前序遍历非常像，区别在于图中可能有环，**必须记录哪些顶点已经访问过**，否则会绕着环无限地走下去。

```c
void dfs(const Graph* g, int v, int* visited)
{
    visited[v] = 1;
    printf("%d ", v);
    for (int i = 0; i < g->adj[v].size; ++i) {
        int w = g->adj[v].to[i];
        if (!visited[w]) dfs(g, w, visited);    // 走到一个没去过的邻居，继续深入
    }
}
```

演示中的图有 8 个顶点、9 条边，邻居的顺序和 C 代码中邻接表的顺序完全相同。注意右侧的调用栈：走到 7 时递归最深；每当一个顶点的邻居都处理完了，就返回上一层，看上一个顶点的下一个邻居：

```c
Graph g = graphCreate(8);
int edges[][2] = {{0, 1}, {0, 2}, {1, 3}, {1, 4}, {2, 5}, {3, 6}, {4, 6}, {5, 7}, {6, 7}};
for (int i = 0; i < 9; ++i) addEdge(&g, edges[i][0], edges[i][1]);
int visited[8] = {0};
printf("DFS: "); dfs(&g, 0, visited); printf("\n");
```

```
DFS: 0 1 3 6 4 7 5 2 
```

DFS 实际走过的边（演示中的绿色边）组成了一棵树，叫作 **DFS 树**。每个顶点访问一次，每条边检查两次（两个方向），时间复杂度 **O(n + m)**。

## 4. 广度优先搜索

**广度优先搜索**（BFS）则是**由近及远**：先访问起点的所有邻居，再访问邻居的邻居……就像往水中扔一块石头，波纹一圈一圈地扩散。和树的层序遍历一样，它用一个**队列**实现：

```c
void bfs(const Graph* g, int s, int* dist)
{
    int* queue = malloc(g->n * sizeof(int));
    int head = 0, tail = 0;
    for (int i = 0; i < g->n; ++i) dist[i] = -1;    // -1 表示还没有访问
    dist[s] = 0;
    queue[tail++] = s;
    while (head < tail) {
        int v = queue[head++];
        printf("%d ", v);
        for (int i = 0; i < g->adj[v].size; ++i) {
            int w = g->adj[v].to[i];
            if (dist[w] == -1) {
                dist[w] = dist[v] + 1;          // 第一次到达 w，经过的边数一定最少
                queue[tail++] = w;
            }
        }
    }
    free(queue);
}
```

这里每个顶点最多入队一次，所以队列用一个长度为 n 的数组就够了，不需要循环。`dist` 数组同时起到了 `visited` 的作用。

### 4.1 BFS 求最短路径

BFS 有一个重要的性质：**顶点按照到起点的距离（边数）从小到大的顺序出队**。距离为 1 的顶点都在距离为 2 的之前出队，距离为 2 的都在距离为 3 的之前……所以**一个顶点第一次被发现时，得到的就是到起点的最少边数**。

这让 BFS 可以求解**无权图的最短路径**：迷宫中从起点到终点最少走几步、社交网络中两个人之间隔着几个人、游戏中的寻路。注意，这只适用于每条边的「长度」都相同的情况。边有不同权重时，要用下一篇的 Dijkstra 算法。

DFS 不能求最短路径：它先找到的路径往往是绕远的。

## 5. 连通分量

一个无向图可能不是连通的，而是由几个互不相连的部分组成，每个部分叫一个**连通分量**。求连通分量的方法是：对每个还没有访问过的顶点，从它出发做一次 DFS（或 BFS），这次搜索能访问到的所有顶点就是一个连通分量。

```c
int countComponents(const Graph* g)
{
    int* visited = calloc(g->n, sizeof(int));
    int count = 0;
    for (int v = 0; v < g->n; ++v) {
        if (!visited[v]) {
            printf("  分量 %d:", ++count);
            printf(" "); dfs(g, v, visited); printf("\n");
        }
    }
    free(visited);
    return count;
}
```

对一个有 7 个顶点、边为 0-1、1-2、3-4、5-6 的图：

```
连通分量:
  分量 1: 0 1 2 
  分量 2: 3 4 
  分量 3: 5 6 
共 3 个
```

所有的程序都用 `-fsanitize=address,undefined` 和 `leaks` 检查过。

## 6. DFS 和 BFS 的比较

| | DFS | BFS |
|---|---|---|
| 数据结构 | 栈（递归调用栈） | 队列 |
| 访问顺序 | 一条路走到底 | 由近及远 |
| 时间复杂度 | O(n + m) | O(n + m) |
| 额外空间 | O(n)（最坏递归深度 n） | O(n)（队列） |
| 典型用途 | 连通分量、判环、拓扑排序（第 4.4 篇）、回溯搜索 | 无权图最短路径、按层处理 |

注意 DFS 的递归深度：对一条有 10 万个顶点的链，递归深度是 10 万，可能导致栈溢出。这时可以像《二叉树与遍历》中那样，改用显式的栈。

## 7. 常见错误

1. **没有记录已访问的顶点**：图中有环时陷入死循环。
2. **BFS 在出队时才标记已访问**：同一个顶点可能被多次入队，队列变长，甚至超出数组的大小。应该**入队时**就标记。
3. **无向图只存了一个方向的边**：从另一端无法走过来。
4. **用 DFS 求最短路径**：DFS 找到的路径不一定最短。
5. **稀疏图用邻接矩阵**：内存爆炸。
6. **对很大的图用递归 DFS**：栈溢出。

## 8. 小结

- 图描述多对多的关系；稀疏图用邻接表（O(n + m) 空间），稠密图可以用邻接矩阵（O(n²)）；实测稀疏图上两者内存相差 400 多倍
- DFS 一条路走到底再回退，用栈（递归）；BFS 由近及远，用队列；都要记录已访问的顶点，都是 O(n + m)
- BFS 中顶点按距离从小到大出队，可以求无权图的最短路径
- 对每个未访问的顶点做一次搜索，可以求出连通分量

## 9. 练习

1. 一个 5 × 7 的迷宫，`S` 是起点（左上角），`E` 是终点（右下角），`#` 是墙，每步可以向上下左右走一格。用 BFS 求从 S 到 E 最少要走几步：

   ```
   S.#....
   .##.##.
   ...#...
   .#...#.
   ...#..E
   ```

2. 用 DFS 判断一个无向图中是否有环。
3. 社交网络有 10 亿个用户，平均每人 200 个好友。应该用邻接矩阵还是邻接表？各需要多少内存（粗略估算）？

1. 把每个格子看作一个顶点，相邻的非墙格子之间有边，从 S 做 BFS：

   ```c
   int shortestPath(void)
   {
       int dist[R][C];
       memset(dist, -1, sizeof dist);
       int qr[R * C], qc[R * C], head = 0, tail = 0;
       qr[tail] = 0; qc[tail++] = 0; dist[0][0] = 0;
       int dr[] = {-1, 1, 0, 0}, dc[] = {0, 0, -1, 1};
       while (head < tail) {
           int r = qr[head], c = qc[head++];
           if (maze[r][c] == 'E') return dist[r][c];
           for (int k = 0; k < 4; ++k) {               // 上下左右四个邻居
               int nr = r + dr[k], nc = c + dc[k];
               if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
               if (maze[nr][nc] == '#' || dist[nr][nc] != -1) continue;
               dist[nr][nc] = dist[r][c] + 1;
               qr[tail] = nr; qc[tail++] = nc;
           }
       }
       return -1;
   }
   ```

   结果是 10 步。网格图不需要显式地存储边，邻居可以直接计算出来。

2. DFS 时，如果遇到一个**已经访问过、但不是当前顶点的父节点**的邻居，就说明有环（父节点要排除，因为无向边在两个方向都存了）：

   ```c
   int hasCycleFrom(int v, int parent, int* visited, int n)
   {
       visited[v] = 1;
       for (int w = 0; w < n; ++w) {
           if (!adjm[v][w]) continue;
           if (!visited[w]) {
               if (hasCycleFrom(w, v, visited, n)) return 1;
           } else if (w != parent) {
               return 1;
           }
       }
       return 0;
   }
   ```

   链 0-1-2-3-4 返回 0；加上边 4-1 后返回 1。（这里为了简短用了邻接矩阵。）

3. 邻接矩阵需要 (10⁹)² = 10¹⁸ 个位置，即使每个位置只用 1 位，也要约 125 PB，不可能。邻接表：一共约 10⁹ × 200 = 2 × 10¹¹ 个邻居记录（每条边存两次），每个用 4 字节的整数存储，约 800 GB，再加上 10⁹ 个顶点的列表头。虽然也很大，但可以分布在多台机器上。这也是为什么真实的社交网络要用专门的图数据库。

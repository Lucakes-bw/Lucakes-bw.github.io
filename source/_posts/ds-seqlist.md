> **本文目标**：理解线性表的概念和顺序存储；实现一个可以自动扩容的顺序表；掌握插入、删除的过程和复杂度；理解为什么扩容要按倍数增长，会用均摊分析解释它；知道顺序表适合和不适合的场景。
>
> **前置知识**：《复杂度分析》，C 语言的《动态内存》（`malloc`、`realloc`）。

## 1. 线性表

**线性表**是 n 个相同类型的元素组成的**有限序列**：除了第一个元素，每个元素都有唯一的前驱；除了最后一个元素，每个元素都有唯一的后继。学生名单、待办事项、一行文字中的字符，都是线性表。

线性表有两种存储方式：

- **顺序存储**：元素依次存放在**一段连续的内存**中，也就是数组。这就是本文的**顺序表**。
- **链式存储**：每个元素单独存放，通过指针把它们串起来。这是下一篇的**链表**。

## 2. 顺序表的结构

C 语言的数组长度是固定的。为了能不断地添加元素，顺序表用 `malloc` 申请一块内存，空间不够时再扩大：

```c
typedef struct {
    int* data;
    size_t size;                                // 元素个数
    size_t capacity;                            // 已分配的空间能容纳的元素个数
} SeqList;

int seqInit(SeqList* s, size_t capacity)
{
    s->data = malloc(capacity * sizeof(int));
    if (s->data == NULL) return 0;
    s->size = 0;
    s->capacity = capacity;
    return 1;
}

void seqFree(SeqList* s)
{
    free(s->data);
    s->data = NULL;
    s->size = s->capacity = 0;
}
```

要分清两个量：**`size` 是实际存放的元素个数，`capacity` 是已经分配的空间大小**，总有 `size <= capacity`。这和 C++ 的 `std::vector` 完全一样（《STL 容器》）。

**按下标访问**是顺序表最大的优势：第 i 个元素的地址是「首地址 + i × 元素大小」，直接计算就能得到，**时间复杂度 O(1)**，这叫**随机访问**。

## 3. 插入和删除

```c
static int grow(SeqList* s)
{
    size_t newCap = s->capacity * 2;
    int* p = realloc(s->data, newCap * sizeof(int));
    if (p == NULL) return 0;
    s->data = p;
    s->capacity = newCap;
    return 1;
}

int insertAt(SeqList* s, size_t pos, int value)
{
    if (pos > s->size) return 0;
    if (s->size == s->capacity && !grow(s)) return 0;
    for (size_t i = s->size; i > pos; --i) {
        s->data[i] = s->data[i - 1];            // 从后往前，依次后移一位
    }
    s->data[pos] = value;
    s->size++;
    return 1;
}

int removeAt(SeqList* s, size_t pos, int* out)
{
    if (pos >= s->size) return 0;
    if (out != NULL) *out = s->data[pos];
    for (size_t i = pos; i + 1 < s->size; ++i) {
        s->data[i] = s->data[i + 1];            // 从前往后，依次前移一位
    }
    s->size--;
    return 1;
}

int pushBack(SeqList* s, int value) { return insertAt(s, s->size, value); }
```

顺序表的元素必须连续存放，中间不能有空位。所以：

- **在 pos 插入**：先把 pos 及之后的元素都**向后移一位**，腾出位置，再放入新元素。移动必须**从后往前**进行，否则后一个元素还没有挪走就被覆盖了。
- **删除 pos**：把 pos 之后的元素都**向前移一位**，填补空位，这次要**从前往后**移动。

### 3.1 复杂度

| 操作 | 时间复杂度 | 说明 |
|---|---|---|
| 按下标访问、修改 | O(1) | 直接计算地址 |
| 在末尾插入 `pushBack` | 均摊 O(1) | 不需要移动元素，偶尔扩容（见第 4 节） |
| 在位置 pos 插入 | O(n) | 要移动 size - pos 个元素 |
| 删除位置 pos | O(n) | 要移动 size - pos - 1 个元素 |
| 删除最后一个元素 | O(1) | 不需要移动 |
| 按值查找 | O(n) | 逐个比较 |

在头部插入是最坏情况，每次都要移动全部元素。实测在头部和末尾各插入 n 个元素（`-O2`）：

```
n = 10000   末尾插入 0.007 ms，头部插入 4.5 ms
n = 100000  末尾插入 0.040 ms，头部插入 321.4 ms
```

n 扩大 10 倍，头部插入的总时间扩大了约 70 倍：每次插入 O(n)，n 次就是 O(n²)。

## 4. 扩容策略

空间满了以后，扩大到多少合适？试试三种策略：每次增加 100 个、每次变为 1.5 倍、每次变为 2 倍。连续在末尾插入 n 个元素，统计扩容时总共复制了多少个元素：

```c
size_t newCap = policy == ADD_CONST ? cap + 100 : policy == MUL_1_5 ? cap + cap / 2 : cap * 2;
int* p = malloc(newCap * sizeof(int));       // 用 malloc + 复制，统计真实的复制次数
for (size_t k = 0; k < size; ++k) p[k] = data[k];
copies += size;
```

```
每次 +100 n = 100000   扩容   1000 次，复制元素     49954000 次（平均每次 push 499.54 次），     7.7 ms
每次 ×1.5 n = 100000   扩容     26 次，复制元素       276515 次（平均每次 push 2.77 次），     0.1 ms
每次 ×2 n = 100000   扩容     15 次，复制元素       131068 次（平均每次 push 1.31 次），     0.1 ms
每次 +100 n = 1000000  扩容  10000 次，复制元素   4999540000 次（平均每次 push 4999.54 次），   367.7 ms
每次 ×1.5 n = 1000000  扩容     31 次，复制元素      2099747 次（平均每次 push 2.10 次），     0.7 ms
每次 ×2 n = 1000000  扩容     18 次，复制元素      1048572 次（平均每次 push 1.05 次），     0.4 ms
```

插入 100 万个元素：

- **每次加 100**：扩容 1 万次，一共复制了**近 50 亿次**元素，平均每插入一个元素要复制 5000 次，而且这个数字随 n 线性增长，总的复杂度是 O(n²)。
- **每次乘以 2**：只扩容 18 次，一共复制了约 100 万次，**平均每次插入只复制 1 次**；乘以 1.5 是 2 次。

### 4.1 均摊分析

为什么按倍数扩容，平均代价是常数？以每次翻倍为例，从容量 1 开始插入 n 个元素，扩容时复制的元素个数依次是 1, 2, 4, 8, …，最多到 n，总和是

1 + 2 + 4 + … + n < 2n

把这不到 2n 次的复制**平均分摊**到 n 次插入上，每次插入平均复制不到 2 次，所以 `pushBack` 的**均摊时间复杂度是 O(1)**。实测的 1.05 次也印证了这一点。

而每次增加固定的 c 个，扩容次数是 n/c，第 k 次扩容复制约 k × c 个元素，总和约为 n²/(2c)，平均每次插入 O(n)。

倍数选 2 还是 1.5？倍数越大，扩容次数越少，但浪费的空间越多（最多浪费将近一半）。GCC 和 Clang 的 `std::vector` 用 2 倍，MSVC 用 1.5 倍，都是合理的选择。

> 删除元素后要不要缩小空间？一种做法是 size 降到容量的 1/4 时缩小一半。注意不能是 1/2：如果容量刚好在临界点，交替地插入和删除，每次都会触发扩容或缩容，每次操作都变成了 O(n)。

## 5. 顺序表的优缺点

**优点**：

- 随机访问 O(1)；
- 元素连续存放，**对 CPU 缓存友好**，遍历速度很快（《STL 容器》中实测 `vector` 的遍历比 `list` 快 10 倍以上）；
- 除了数据本身，几乎没有额外的空间开销。

**缺点**：

- 在中间或头部插入、删除需要移动元素，O(n)；
- 扩容时要复制全部元素，而且会让原来的指针失效（《动态内存》中的 `realloc`）；
- 可能有一部分已分配的空间没有使用。

**适合**：以读取和遍历为主、主要在末尾增删的场景。这也是为什么 `vector` 是 C++ 中最常用的容器。需要频繁在头部或中间插入删除时，可以考虑下一篇的链表。

## 6. 常见错误

1. **插入时从前往后移动**：后面的元素被覆盖，最后所有位置都变成了同一个值。
2. **插入位置的检查写成 `pos >= size`**：在末尾插入（`pos == size`）是合法的。
3. **扩容写成 `s->data = realloc(s->data, ...)`**：失败时原来的内存泄漏。
4. **扩容按固定大小增长**：总代价变成 O(n²)。
5. **扩容后继续使用指向旧内存的指针**：`realloc` 可能移动了数据。
6. **混淆 size 和 capacity**：访问 `data[size]` 到 `data[capacity - 1]` 读到的是未初始化的值。

## 7. 小结

- 顺序表用连续的内存存放元素，按下标访问 O(1)
- 插入要把后面的元素从后往前后移，删除要从前往后前移，都是 O(n)；在末尾操作不需要移动
- 空间满了按倍数扩容，`pushBack` 均摊 O(1)；实测 100 万次插入，每次加 100 复制了 50 亿次，每次翻倍只复制了约 100 万次
- 顺序表对缓存友好、空间紧凑，适合以读取和末尾增删为主的场景

## 8. 练习

1. 写一个函数 `size_t removeAll(SeqList* s, int value)`，删除顺序表中所有等于 `value` 的元素，返回删除的个数。要求时间复杂度 O(n)。（如果每找到一个就调用一次 `removeAt`，复杂度是多少？）
2. 从容量 1 开始，每次扩容为原来的 2 倍，连续插入 1000 个元素，一共会扩容几次？最终的容量是多少？
3. 为什么 `pushBack` 的复杂度要说「均摊 O(1)」而不是「O(1)」？

<details>
<summary>点击查看答案</summary>

1. 用两个下标：`i` 遍历所有元素，`k` 指向下一个要保留的元素应该放的位置，只把不等于 `value` 的元素复制到前面：

   ```c
   size_t removeAll(SeqList* s, int value)
   {
       size_t k = 0;                                   // 下一个保留元素要放的位置
       for (size_t i = 0; i < s->size; ++i) {
           if (s->data[i] != value) {
               s->data[k++] = s->data[i];
           }
       }
       size_t removed = s->size - k;
       s->size = k;
       return removed;
   }
   ```

   对 `{3, 1, 3, 3, 2, 3, 5}` 删除 3，返回 4，剩下 `1 2 5`。每个元素只被访问一次，O(n)。如果每找到一个就调用 `removeAt`，每次删除都要移动后面的元素，最坏情况是 O(n²)。这个写法和 C++ 的 erase-remove 惯用法（《迭代器与算法》）的思路是一样的。

2. 容量依次变为 2, 4, 8, …, 1024，一共扩容 10 次，最终容量 1024。

3. 大多数 `pushBack` 只是写入一个元素，是 O(1) 的；但偶尔有一次需要扩容，这一次是 O(n) 的。所以**单次**操作的最坏情况是 O(n)。只有把扩容的代价平均到所有操作上，每次才是 O(1)。如果程序对单次操作的延迟有严格要求（比如实时系统），就要注意这一点，可以用 `reserve` 预先分配好空间。

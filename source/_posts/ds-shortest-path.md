## 1. 问题

在**带权图**中，每条边有一个非负的长度（距离、时间、费用）。**单源最短路径**问题是：从一个起点 s 出发，到其他每个顶点的最短距离是多少，怎么走。

上一篇的 BFS 只能处理所有边长度都相同的情况。边的长度不同时，「经过的边少」不代表「距离短」：两条长度为 2 的边比一条长度为 10 的边更近。

带权图用邻接表存储，每条边记录终点和权重：

```c
typedef struct { int to; int w; } Edge;
typedef struct { Edge* e; int size, cap; } EdgeList;
typedef struct { int n; EdgeList* adj; } WGraph;
```

## 2. 松弛

所有最短路径算法都基于一个操作，叫作**松弛**（relax）：用 `dist[v]` 记录目前已知的从 s 到 v 的最短距离（一开始是 ∞），如果发现了一条经过 u 再到 v 的路更短，就更新它：

```c
if (dist[u] + w < dist[v]) {        // 经过 u 到 v 更近
    dist[v] = dist[u] + w;
    prev[v] = u;                    // 记下 v 的前驱，用来还原路径
}
```

## 3. Dijkstra 算法

1959 年，Edsger Dijkstra 提出了这样的方法：

1. `dist[s] = 0`，其他顶点的 `dist` 为 ∞；
2. 在**还没有确定**的顶点中，选出 `dist` **最小的**顶点 u，它的最短距离就**确定**了；
3. 用 u 松弛它的所有邻居；
4. 重复 2、3，直到所有顶点都确定。

为什么 u 的最短距离在第 2 步就确定了？因为所有边的长度都**非负**：其他还没有确定的顶点的 `dist` 都不比 u 小，经过它们再绕到 u，只会更长，不可能更短。

这又是一种**贪心**策略：每次只处理当前最近的顶点。

### 3.1 朴素实现

```c
void dijkstraNaive(const WGraph* g, int s, long long* dist, int* prev)
{
    int* done = calloc(g->n, sizeof(int));
    for (int i = 0; i < g->n; ++i) { dist[i] = INF; prev[i] = -1; }
    dist[s] = 0;
    for (int round = 0; round < g->n; ++round) {
        int u = -1;
        for (int i = 0; i < g->n; ++i)          // 在没有确定的顶点中找 dist 最小的
            if (!done[i] && dist[i] != INF && (u == -1 || dist[i] < dist[u])) u = i;
        if (u == -1) break;                     // 剩下的都不可达
        done[u] = 1;                            // u 的最短距离确定了
        for (int i = 0; i < g->adj[u].size; ++i) {
            Edge e = g->adj[u].e[i];
            if (dist[u] + e.w < dist[e.to]) {   // 松弛：经过 u 到 e.to 更近
                dist[e.to] = dist[u] + e.w;
                prev[e.to] = u;
            }
        }
    }
    free(done);
}
```

（`INF` 定义为 `LLONG_MAX`，`dist` 用 `long long`，防止距离很大时溢出。）

每轮扫描所有顶点找最小值是 O(n)，一共 n 轮，总的时间复杂度是 **O(n²)**。

### 3.2 堆优化

「找 dist 最小的顶点」正是优先队列擅长的事。把 `(距离, 顶点)` 放进小顶堆，每次取出最小的：

```c
void dijkstra(const WGraph* g, int s, long long* dist, int* prev)
{
    PQ q = {NULL, 0, 0};
    for (int i = 0; i < g->n; ++i) { dist[i] = INF; prev[i] = -1; }
    dist[s] = 0;
    pqPush(&q, (Item){0, s});
    while (q.size > 0) {
        Item it = pqPop(&q);
        int u = it.v;
        if (it.d > dist[u]) continue;           // 过期的记录：u 已经用更短的距离处理过了
        for (int i = 0; i < g->adj[u].size; ++i) {
            Edge e = g->adj[u].e[i];
            if (dist[u] + e.w < dist[e.to]) {
                dist[e.to] = dist[u] + e.w;
                prev[e.to] = u;
                pqPush(&q, (Item){dist[e.to], e.to});   // 不删除旧记录，直接放入新记录
            }
        }
    }
    free(q.a);
}
```

`PQ`、`pqPush`、`pqPop` 是一个按距离排序的小顶堆，和《堆与优先队列》中的实现相同，元素换成了 `(d, v)` 对。

一个顶点的 `dist` 可能被更新好几次，每次更新都会放入一条新记录。堆不支持高效地修改或删除中间的元素，所以这里采用「**懒删除**」：旧的记录留在堆里，取出时如果发现它的距离比 `dist` 中记录的大，说明是过期的，直接跳过。

每条边最多放入一条记录，堆的大小是 O(m)，每次操作 O(log m) = O(log n)，总的时间复杂度是 **O((n + m) log n)**。

### 3.3 还原路径

`prev[v]` 记录了最短路径上 v 的前一个顶点。从终点沿着 `prev` 往回走到起点，就得到了路径（倒序的），用递归可以正序输出：

```c
void printPath(const int* prev, int v)
{
    if (prev[v] != -1) { printPath(prev, prev[v]); printf(" → "); }
    printf("%d", v);
}
```

对演示中的图（`addEdge` 的参数是两个端点和长度）：

```c
WGraph g = wgCreate(6);
int E[][3] = {{0, 1, 7}, {0, 2, 9}, {0, 5, 14}, {1, 2, 10}, {1, 3, 15}, {2, 3, 11}, {2, 5, 2}, {3, 4, 6}, {4, 5, 9}};
for (int i = 0; i < 9; ++i) addEdge(&g, E[i][0], E[i][1], E[i][2]);
long long dist[6]; int prev[6];
dijkstra(&g, 0, dist, prev);
```

```
到 0 的距离 0，路径 0
到 1 的距离 7，路径 0 → 1
到 2 的距离 9，路径 0 → 2
到 3 的距离 20，路径 0 → 2 → 3
到 4 的距离 20，路径 0 → 2 → 5 → 4
到 5 的距离 11，路径 0 → 2 → 5
```

注意到 5 的最短路：直接走边 0–5 长度是 14，而绕道 0 → 2 → 5 只有 9 + 2 = 11。

### 3.4 实测

在随机生成的稀疏图（每个顶点平均 6 条边，长度 1 到 100）上，比较两种实现（`-O2`），并检查结果一致：

```
n = 10000   m ≈ 30000：朴素版     90.3 ms，堆优化版   0.96 ms，结果一致
n = 100000  m ≈ 300000：朴素版   7406.2 ms，堆优化版  13.11 ms，结果一致
```

10 万个顶点时，朴素版用了 7.4 秒，堆优化版只用了 13 毫秒，**快了 560 多倍**。稀疏图上，O((n + m) log n) 远小于 O(n²)。

（如果图非常稠密，m 接近 n²，堆优化版的 O(n² log n) 反而比朴素版的 O(n²) 慢。地图、网络这样的实际问题几乎都是稀疏图。）

## 4. 负权边

Dijkstra 的正确性依赖于「边的长度非负」。如果有负权边会怎样？看这个有向图：0 → 1 长度 2，0 → 2 长度 5，2 → 1 长度 **-4**，1 → 3 长度 1。

```c
WGraph ng = wgCreate(4);
addArc(&ng, 0, 1, 2); addArc(&ng, 0, 2, 5); addArc(&ng, 2, 1, -4); addArc(&ng, 1, 3, 1);
dijkstraNaive(&ng, 0, dist, prev);
```

```
负权边：dist[1] = 1，dist[3] = 3（实际最短：0→2→1 = 1，0→2→1→3 = 2）
```

过程是这样的：1 的距离是 2，比 2 的距离 5 小，所以 1 先被「确定」，然后用它算出了 3 的距离 2 + 1 = 3。之后处理 2 时才发现，绕道 2 到 1 只要 5 - 4 = 1，比 2 还短。`dist[1]` 被改成了 1，但 3 早已用旧的值算过了，它的距离停留在了错误的 3。

**有负权边时，「当前最近的顶点已经确定」这个结论不再成立。** 这时要用 Bellman-Ford 等算法（对所有边反复松弛 n - 1 轮，O(nm)）。如果图中有总长度为负的环，沿着环绕圈距离可以无限小，最短路径就没有意义了。

## 5. Floyd 算法

如果要求**任意两个顶点之间**的最短距离，可以对每个顶点运行一次 Dijkstra，也可以用更简洁的 **Floyd 算法**：

```c
void floyd(int n, long long d[][6])
{
    for (int k = 0; k < n; ++k)                 // 允许经过 0..k 作为中转
        for (int i = 0; i < n; ++i)
            for (int j = 0; j < n; ++j)
                if (d[i][k] != INF && d[k][j] != INF && d[i][k] + d[k][j] < d[i][j])
                    d[i][j] = d[i][k] + d[k][j];
}
```

`d` 是邻接矩阵，初始时 `d[i][j]` 是边的长度（没有边为 ∞，`d[i][i]` 为 0）。外层循环的含义是：第 k 轮结束后，`d[i][j]` 是「只允许经过顶点 0 到 k 作为中转」时的最短距离。所有 n 轮结束后，就允许经过任何顶点了。

```
Floyd: 3 到 5 的距离 13，4 到 1 的距离 21
```

Floyd 的时间复杂度是 **O(n³)**，空间 O(n²)，代码只有几行，适合顶点数不多（几百个以内）的情况。**三层循环的顺序不能变**：k 必须在最外层。它也能处理负权边（但不能有负环）。

所有的程序都用 `-fsanitize=address,undefined` 和 `leaks` 检查过。

## 6. 常见错误

1. **在有负权边的图上用 Dijkstra**：结果错误，而且不会有任何提示。
2. **`dist` 的初值 ∞ 用 `INT_MAX`，再做加法**：`INT_MAX + w` 溢出成负数。要先判断是否为 ∞，或者用一个足够大但不会溢出的值。
3. **堆优化版没有跳过过期的记录**：同一个顶点被处理多次，虽然结果可能还是对的，但效率下降。
4. **Floyd 的三层循环把 k 放在了里面**：结果错误。
5. **稠密图用堆优化，稀疏图用朴素版**：选择反了。
6. **只求距离，忘了记录前驱**：无法给出具体的路径。

## 7. 小结

- 松弛：如果经过 u 到 v 更近，就更新 `dist[v]` 和 `prev[v]`
- Dijkstra：每次取出未确定的顶点中距离最小的，它的距离就确定了，再松弛它的邻居；要求边非负
- 朴素版 O(n²)；用堆优化（懒删除）是 O((n + m) log n)，实测 10 万个顶点快了 560 多倍
- 沿着 `prev` 回溯得到路径；所有顶点的前驱组成最短路径树
- 负权边会让 Dijkstra 算错；任意两点间的最短路径可以用 Floyd，O(n³)

## 8. 练习

1. 对演示中的图，用 Floyd 算法求出的 3 到 5、4 到 1 的最短距离分别是 13 和 21，分别写出对应的路径。
2. 如果所有边的长度都是 1，Dijkstra 算法和 BFS 的执行过程有什么关系？
3. 有一种说法：「把所有边都加上一个足够大的常数，让它们都变成正数，就可以用 Dijkstra 处理负权边了。」这对吗？

<details>
<summary>点击查看答案</summary>

1. 3 到 5：3 → 2 → 5，11 + 2 = 13（直接走 3 → 4 → 5 是 6 + 9 = 15）。4 到 1：4 → 5 → 2 → 1，9 + 2 + 10 = 21（走 4 → 3 → 1 是 6 + 15 = 21，同样长）。

2. 边长都是 1 时，优先队列中的距离是 0, 1, 1, 2, 2, 2, …，取出的顺序就是按距离分层的顺序，和 BFS 中队列的出队顺序本质上一样。BFS 可以看作 Dijkstra 在所有边长相等时的特例，它用普通队列代替了优先队列，从 O((n + m) log n) 降到了 O(n + m)。

3. 不对。加上常数后，**经过边数多的路径**增加的长度更多，最短路径可能改变。比如 0 → 1 长度 2，0 → 2 → 1 长度 5 + (-4) = 1；每条边加 4 之后，0 → 1 变成 6，0 → 2 → 1 变成 9 + 0 = 9，最短路径从「绕道」变成了「直接走」，答案不同了。

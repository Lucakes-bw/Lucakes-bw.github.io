> **本文目标**：掌握并查集的查找和合并，理解路径压缩和按秩合并；理解最小生成树；会实现 Kruskal 和 Prim 算法，知道如何选择。

> **前置知识**：《图的表示与遍历》、《最短路径》。

## 1. 问题

要在 6 个城市之间铺设光缆，城市之间的铺设费用各不相同，怎样用最少的总费用让所有城市互相连通？

这就是**最小生成树**（MST，Minimum Spanning Tree）问题。对于一个连通的无向带权图：

- **生成树**：包含所有 n 个顶点、恰好 n - 1 条边的连通子图（没有环，所以是一棵树）；
- **最小生成树**：所有生成树中，边的总权重最小的那一棵。

为什么正好是 n - 1 条边？少了不能连通所有顶点，多了就一定有环，而去掉环上的一条边仍然连通、总权重更小。

## 2. 并查集

最小生成树的 Kruskal 算法需要一个工具：快速判断两个顶点**是否已经连通**，以及把两部分**连接起来**。这就是**并查集**（Union-Find）要做的事。它维护若干个**不相交的集合**，支持两个操作：

- **查找**（find）：一个元素属于哪个集合；
- **合并**（union）：把两个集合合并成一个。

### 2.1 用树表示集合

每个集合用一棵树表示，每个元素记录它的父节点，**根**就是这个集合的代表。查找就是沿着父指针一直走到根；合并就是把一棵树的根挂到另一棵树的根下面。判断两个元素是否在同一个集合中，只要比较它们的根。

```c
typedef struct {
    int* parent;
    int* rank;                                  // 树高的上界
    int count;                                  // 集合的个数
} UnionFind;

UnionFind ufCreate(int n)
{
    UnionFind uf = {malloc(n * sizeof(int)), calloc(n, sizeof(int)), n};
    if (!uf.parent || !uf.rank) exit(1);
    for (int i = 0; i < n; ++i) uf.parent[i] = i;   // 一开始每个元素自成一个集合
    return uf;
}
```

### 2.2 两个优化

不加任何优化，树可能退化成一条长链，查找变成 O(n)。有两个简单而强大的优化：

**按秩合并**：合并时，把**矮的树挂到高的树下面**，这样树的高度增长得很慢。`rank` 记录树高的上界，只有两棵树一样高时，合并后高度才加 1。

**路径压缩**：查找时，把沿途经过的每个节点都**直接挂到根上**。下次再查找这些节点，只需要一步。

```c
int find(UnionFind* uf, int x)
{
    int root = x;
    while (uf->parent[root] != root) root = uf->parent[root];   // 找到根
    while (uf->parent[x] != root) {             // 路径压缩：沿途的节点直接挂到根上
        int next = uf->parent[x];
        uf->parent[x] = root;
        x = next;
    }
    return root;
}

int unite(UnionFind* uf, int a, int b)
{
    int ra = find(uf, a), rb = find(uf, b);
    if (ra == rb) return 0;                     // 已经在同一个集合中
    if (uf->rank[ra] < uf->rank[rb]) { int t = ra; ra = rb; rb = t; }
    uf->parent[rb] = ra;                        // 按秩合并：矮的树挂到高的树下面
    if (uf->rank[ra] == uf->rank[rb]) uf->rank[ra]++;
    uf->count--;
    return 1;
}
```

在演示中，箭头从每个元素指向它的父节点。按提示依次合并，注意合并 5 和 3 时，查找 3 的根会顺便把 3 直接挂到根 0 上：

### 2.3 实测

构造最坏的情况：依次合并 (0, 1)、(1, 2)、(2, 3)……不优化的版本总是把旧的根挂到新元素下面，形成一条长链；然后查找每个元素（`-O2`）：

```
n = 10000   不优化     45.0 ms，路径压缩 + 按秩合并 0.03 ms
n = 100000  不优化   1450.2 ms，路径压缩 + 按秩合并 0.15 ms
```

10 万个元素时，不优化的版本用了 1.45 秒，优化后只用了 0.15 毫秒，**相差近 1 万倍**。可以证明，同时使用两个优化后，每次操作的均摊时间是 O(α(n))，α 是一个增长极慢的函数（反阿克曼函数），对于任何实际的 n，α(n) ≤ 4，可以看作常数。

并查集还有很多其他用途：判断网络中两台计算机是否连通、社交网络中的朋友圈、图像中连通区域的标记。

## 3. Kruskal 算法

Kruskal 算法的思路非常直接：

1. 把所有边**按权重从小到大排序**；
2. 依次考察每条边：如果它的两个端点**不在同一棵树中**，就选择这条边，把两棵树合并；否则选它会形成环，跳过；
3. 选够 n - 1 条边就结束。

「两个端点是否在同一棵树中」正是并查集的查找，「合并两棵树」正是并查集的合并：

```c
typedef struct { int u, v, w; } WEdge;
int byWeight(const void* a, const void* b) { int x = ((const WEdge*)a)->w, y = ((const WEdge*)b)->w; return (x > y) - (x < y); }

long long kruskal(int n, WEdge* edges, int m, WEdge* chosen)
{
    qsort(edges, m, sizeof(WEdge), byWeight);   // 按权重从小到大
    UnionFind uf = ufCreate(n);
    long long total = 0;
    int k = 0;
    for (int i = 0; i < m && k < n - 1; ++i) {
        if (unite(&uf, edges[i].u, edges[i].v)) {   // 两端不在同一棵树中：选这条边
            chosen[k++] = edges[i];
            total += edges[i].w;
        }                                       // 否则会形成环，跳过
    }
    ufFree(&uf);
    return k == n - 1 ? total : -1;             // 选不够 n - 1 条：图不连通
}
```

权重为 9 的两条边 0-2 和 4-5，C 程序和演示选择它们的先后顺序不同（`qsort` 不保证相等元素的顺序，演示中用的 JavaScript 排序是稳定的），但两条都被选中了，最小生成树完全相同。

时间复杂度：排序 O(m log m)，并查集的操作几乎是 O(1)，总共 **O(m log m)**。

为什么这样贪心是对的？对于任意一条被选中的边，它是连接两部分的所有边中最轻的一条（更轻的边都已经考察过，要么被选中、要么在同一部分内部）。可以证明，这样的边一定属于某棵最小生成树。

## 4. Prim 算法

Prim 算法从另一个角度出发：从一个顶点开始，**每次把离当前的树最近的一个顶点加入树中**，直到所有顶点都在树中。它和 Dijkstra 算法的结构几乎一样，只是 `best[v]` 记录的是 v 到**树**的最短边，而不是到**起点**的距离：

```c
long long prim(int n, int w[][6])
{
    int inTree[6] = {0};
    int best[6];                                // 每个顶点到当前树的最短边
    for (int i = 0; i < n; ++i) best[i] = 1 << 30;
    best[0] = 0;
    long long total = 0;
    for (int round = 0; round < n; ++round) {
        int u = -1;
        for (int i = 0; i < n; ++i) if (!inTree[i] && (u == -1 || best[i] < best[u])) u = i;
        inTree[u] = 1;                          // 离树最近的顶点加入树
        total += best[u];
        for (int v = 0; v < n; ++v)
            if (!inTree[v] && w[u][v] && w[u][v] < best[v]) best[v] = w[u][v];
    }
    return total;
}
```

```
Prim 总权重 33
```

这里用邻接矩阵实现，O(n²)；用邻接表加上堆优化（和 Dijkstra 一样），是 O(m log n)。

**如何选择**：Kruskal 以边为中心，适合稀疏图，代码也简单（只要有并查集）；Prim 以顶点为中心，朴素版 O(n²) 不依赖于边数，适合稠密图。

所有的程序都用 `-fsanitize=address,undefined` 和 `leaks` 检查过。

## 5. 常见错误

1. **并查集只比较 `parent[a] == parent[b]`**：要比较两者的**根**，父节点相同只是一种特殊情况。
2. **合并时把 a 挂到 b 下面，而不是把根挂到根下面**：破坏了树的结构，集合会被拆散。
3. **不做优化**：最坏情况下退化成链表，实测慢了近 1 万倍。
4. **Kruskal 中不检查环，直接选最小的 n - 1 条边**：可能形成环，并且没有连通所有顶点。
5. **对不连通的图求最小生成树**：选不够 n - 1 条边，要检查并报告。
6. **把最小生成树和最短路径混淆**：最小生成树中两点之间的路径不一定是最短路径（练习 3）。

## 6. 小结

- 并查集用树表示集合，根是集合的代表；查找走到根，合并把一个根挂到另一个根下面
- 按秩合并让树保持矮小，路径压缩把沿途的节点直接挂到根上；两者结合后均摊几乎 O(1)，实测比不优化快了近 1 万倍
- 最小生成树用 n - 1 条边连通所有顶点，总权重最小
- Kruskal：边按权重排序，用并查集跳过会形成环的边，O(m log m)，适合稀疏图
- Prim：每次加入离树最近的顶点，和 Dijkstra 结构相同，朴素版 O(n²) 适合稠密图

## 7. 练习

1. 对本文的图，从顶点 0 开始运行 Prim 算法，写出顶点加入树的顺序。
2. 一个由 `1`（陆地）和 `0`（水）组成的网格中，上下左右相连的陆地组成一个岛屿。怎样用并查集统计岛屿的个数？
3. 举例说明：最小生成树中两个顶点之间的路径，不一定是这两个顶点之间的最短路径。

1. 从 0 开始：到 1、2、5 的边分别是 7、9、14，加入 1；1 带来了到 3 的 15，到 2 的 10 不比 9 小，加入 2（9）；2 带来了到 5 的 2、到 3 的 11，加入 5（2）；5 带来了到 4 的 9，加入 4（9）；4 带来了到 3 的 6，加入 3（6）。顺序是 0、1、2、5、4、3，总权重 7 + 9 + 2 + 9 + 6 = 33，和 Kruskal 相同。

2. 每个陆地格子是一个元素，把编号设为 `r * 列数 + c`。遍历每个陆地格子，如果它右边或下边的格子也是陆地，就把两者合并。最后，陆地格子中根是自己的个数（或者「陆地格子数 - 成功合并的次数」）就是岛屿数。也可以用上一篇的 DFS / BFS 求连通分量来做。

3. 本文的图中，最小生成树里 1 到 2 的路径是 1 → 0 → 2，长度 7 + 9 = 16；但直接走边 1-2 只有 10。最小生成树只保证所有边的**总和**最小，不保证每两个点之间的路径最短。

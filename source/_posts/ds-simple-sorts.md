> **本文目标**：掌握冒泡排序、选择排序、插入排序；理解排序的稳定性；会分析它们在不同输入下的比较次数和移动次数；知道插入排序在基本有序时的优势。
>
> **前置知识**：《复杂度分析》、《顺序表》。本章所有的排序都按从小到大排列 `int` 数组。

## 1. 排序

**排序**就是把一组数据按照某种顺序重新排列。它是最基础、使用最多的算法之一：数据排好序之后，查找可以用二分查找，去重只需要比较相邻的元素，求中位数直接取中间的那个。

衡量一个排序算法，主要看：

- **时间复杂度**：最好、最坏、平均情况下的比较次数和移动（交换）次数；
- **空间复杂度**：是否需要额外的数组（不需要的叫**原地排序**）；
- **稳定性**：值相同的元素，排序后是否保持原来的先后顺序。

本篇的三种排序思路简单，都是 O(n²) 的；下一篇介绍 O(n log n) 的快速排序和归并排序。

## 2. 三种简单排序

### 2.1 冒泡排序

反复比较**相邻**的两个元素，如果顺序不对就交换。每一轮都会把当前最大的元素「冒泡」到末尾：

```c
void bubbleSort(int* a, int n)
{
    for (int end = n - 1; end > 0; --end) {
        int swapped = 0;
        for (int i = 0; i < end; ++i) {
            if (a[i] > a[i + 1]) {              // 相邻的两个逆序，交换
                int t = a[i]; a[i] = a[i + 1]; a[i + 1] = t;
                swapped = 1;
            }
        }
        if (!swapped) break;                    // 一轮下来没有交换：已经有序
    }
}
```

`swapped` 是一个优化：如果某一轮没有发生任何交换，说明已经有序，可以提前结束。

### 2.2 选择排序

每一轮在**还没排好的部分**中找出最小的元素，和这部分的第一个元素交换：

```c
void selectionSort(int* a, int n)
{
    for (int i = 0; i < n - 1; ++i) {
        int min = i;
        for (int j = i + 1; j < n; ++j) {       // 在 a[i..n-1] 中找最小的
            if (a[j] < a[min]) min = j;
        }
        if (min != i) { int t = a[i]; a[i] = a[min]; a[min] = t; }
    }
}
```

### 2.3 插入排序

就像打牌时整理手中的牌：前面的部分已经排好序，每次取出下一个元素（`key`），在前面找到它的位置插进去，比它大的元素依次后移一位：

```c
void insertionSort(int* a, int n)
{
    for (int i = 1; i < n; ++i) {
        int key = a[i];                         // 要插入的元素
        int j = i - 1;
        while (j >= 0 && a[j] > key) {
            a[j + 1] = a[j];                    // 比 key 大的元素后移一位
            --j;
        }
        a[j + 1] = key;
    }
}
```

在演示中分别运行三种排序，对比它们的比较次数和交换（移动）次数。绿色的柱子是已经确定位置的部分：冒泡排序从右往左确定，选择排序从左往右确定，插入排序则是左边的部分「相对有序」，后面的元素还可能插进来。也可以输入自己的数组，比如已经有序的 `1 2 3 4 5 6 7 8` 或者逆序的 `8 7 6 5 4 3 2 1`：

## 3. 稳定性

如果有两个学生分数相同，按分数排序后，他们原来谁在前面，排序后仍然谁在前面，这样的排序就是**稳定的**。

为什么稳定性重要？在实际中经常需要按多个条件排序，比如先按姓名排好，再按分数排序，希望分数相同的学生仍然按姓名排列。这只有在第二次排序是稳定的时候才能做到。

```c
typedef struct { const char* name; int score; } Student;

Student s1[] = {{"Amy", 90}, {"Bob", 85}, {"Cat", 90}, {"Dan", 85}, {"Eve", 70}};
```

按分数分别用插入排序和选择排序排序（代码和上面相同，只是比较的是 `score`）：

```
插入排序（稳定）: Eve70 Bob85 Dan85 Amy90 Cat90
选择排序（不稳定）: Eve70 Bob85 Dan85 Cat90 Amy90
```

原来 Amy 在 Cat 前面，选择排序之后 Cat 跑到了 Amy 前面。原因是选择排序的**远距离交换**：第一轮找到最小的 Eve，把它和第一个元素 Amy 交换，Amy 被换到了最后，跳过了同样是 90 分的 Cat。

- **冒泡排序**只交换相邻的元素，而且只在 `>` 时交换（相等不交换），是稳定的；
- **插入排序**只把比 `key` 大的元素后移（`a[j] > key`，相等就停下），是稳定的；
- **选择排序**有远距离交换，是不稳定的。

注意比较条件中的等号：如果把插入排序的 `a[j] > key` 写成 `a[j] >= key`，它就不稳定了。

## 4. 实测

对 2 万个元素，分别用随机、已经有序、逆序的数据，统计比较和移动的次数（交换一次计为移动 3 次），以及运行时间（`-O2`），并检查结果都正确地排好了序：

```
n = 20000 随机数据 冒泡排序：比较   199954489 次，移动   299954250 次，  116.3 ms
n = 20000 随机数据 选择排序：比较   199990000 次，移动       59967 次，  266.4 ms
n = 20000 随机数据 插入排序：比较   100004739 次，移动   100004749 次，   24.7 ms
n = 20000 有序数据 冒泡排序：比较       19999 次，移动           0 次，    0.0 ms
n = 20000 有序数据 选择排序：比较   199990000 次，移动           0 次，  253.9 ms
n = 20000 有序数据 插入排序：比较       19999 次，移动       19999 次，    0.0 ms
n = 20000 逆序数据 冒泡排序：比较   199990000 次，移动   599970000 次，   51.1 ms
n = 20000 逆序数据 选择排序：比较   199990000 次，移动       30000 次，  258.9 ms
n = 20000 逆序数据 插入排序：比较   199990000 次，移动   200009999 次，   58.2 ms
```

（插入排序中每次后移和最后放入 `key` 各计为 1 次移动。）

从这些数字可以看出：

- **选择排序**无论输入是什么，比较次数都是 n(n-1)/2 ≈ 2 亿次，但移动次数最少（最多 n-1 次交换）。
- **冒泡排序和插入排序**在有序数据上只比较了 n-1 次，是 **O(n)** 的；在逆序数据上最慢。
- 在随机数据上，**插入排序**的比较和移动次数大约都是 n²/4，比冒泡排序少一半，实际运行也最快。

运行时间和次数并不完全成比例。比如选择排序的移动次数最少，却是最慢的；冒泡排序在逆序数据上的操作次数比随机数据更多，却更快。一个重要的原因是现代 CPU 会**预测分支**：逆序数据中「是否交换」每次都是「是」，很容易预测；随机数据中则无法预测，每次预测失败都要付出代价。而选择排序在内层循环中更新 `min`，前后两次比较互相依赖，CPU 难以并行执行。**操作次数是分析的基础，但最终要以实测为准。**

| 排序 | 最好 | 平均 | 最坏 | 空间 | 稳定 |
|---|---|---|---|---|---|
| 冒泡排序 | O(n) | O(n²) | O(n²) | O(1) | 是 |
| 选择排序 | O(n²) | O(n²) | O(n²) | O(1) | 否 |
| 插入排序 | O(n) | O(n²) | O(n²) | O(1) | 是 |

### 4.1 插入排序与基本有序的数据

插入排序的移动次数等于数组中**逆序对**的个数（前面比后面大的元素对）。数据越接近有序，逆序对越少，插入排序就越快。实测 10 万个元素，在有序的基础上随机交换 1% 的相邻元素：

```
n = 100000 基本有序（1% 相邻交换）：插入排序比较 100989 次，0.28 ms
n = 100000 随机数据：插入排序比较 2502451649 次，663.8 ms
```

基本有序时只比较了约 10 万次（几乎是 n），随机数据则是 25 亿次。

这就是为什么**实际的排序库中都有插入排序**：快速排序把数组分到很小（比如 16 个元素以内）时，改用插入排序来处理，因为此时数据量小、常数小；而且很多实际数据本身就是基本有序的（比如在一个已经排好序的列表末尾追加了几条记录）。

所有的程序都用 `-fsanitize=address,undefined` 检查过。

## 5. 常见错误

1. **冒泡排序的内层循环写成 `i < n - 1`，每轮都比较到末尾**：结果正确，但做了很多无用的比较。每轮之后末尾的部分已经排好了。
2. **插入排序的 `while` 条件中先比较再检查下标**：`a[j] > key && j >= 0` 在 j = -1 时会越界访问。要先检查 `j >= 0`，利用短路求值。
3. **插入排序中先覆盖 `a[i]` 再保存 `key`**：要插入的元素丢失了。
4. **比较条件中多写了等号**：冒泡和插入排序变得不稳定。
5. **以为 O(n²) 的排序没有用**：数据量小或者基本有序时，插入排序是最快的选择。

## 6. 小结

- 冒泡排序比较相邻元素并交换，每轮把最大的放到末尾；有序时可以提前结束
- 选择排序每轮选出最小的放到前面，比较次数固定为 n(n-1)/2，交换最少，但不稳定
- 插入排序把每个元素插入前面已排好的部分，移动次数等于逆序对的个数；基本有序时接近 O(n)
- 稳定性：值相同的元素保持原来的顺序；远距离交换会破坏稳定性
- 三者都是 O(n²)、原地排序；实测随机数据上插入排序最快，基本有序时只需线性时间

2. 对 n 个元素，选择排序最多交换几次？在什么情况下比较有用？
3. 插入排序中，可以用二分查找来找 `key` 应该插入的位置。这样改进之后，时间复杂度变成多少？

1. 第 1 轮比较 4 次，交换了 2 和 1；第 2 轮比较 3 次，没有交换，提前结束。一共 2 轮、7 次比较。

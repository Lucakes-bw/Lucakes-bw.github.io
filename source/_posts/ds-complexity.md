## 1. 为什么需要复杂度分析

同一个问题，往往有很多种解法。比如「判断数组中有没有重复的元素」：

- 方法一：拿每个元素和它后面的所有元素比较一遍；
- 方法二：先排序，排序后重复的元素一定相邻，再扫描一遍。

哪种方法更好？最直接的办法是写出来，跑一跑，看看哪个快。但运行时间受很多因素影响：电脑的快慢、编译器的优化、数据的规模和分布……在 1000 个数据上更快的方法，在 100 万个数据上可能慢得无法接受。

我们需要一个**与机器无关**、能反映**数据量变大时运行时间怎样增长**的衡量方法，这就是**复杂度分析**。

## 2. 大 O 表示法

### 2.1 数一数基本操作的次数

先看方法一的代码：

```c
int hasDupQuadratic(const int* a, int n)
{
    for (int i = 0; i < n; ++i)
        for (int j = i + 1; j < n; ++j)
            if (a[i] == a[j]) return 1;
    return 0;
}
```

没有重复元素时（最坏情况），比较 `a[i] == a[j]` 执行了多少次？i = 0 时比较 n-1 次，i = 1 时比较 n-2 次……一共是

(n-1) + (n-2) + … + 1 + 0 = n(n-1)/2 = 0.5n² - 0.5n

当 n 很大时，起决定作用的是 **n²** 这一项：n = 10 万时，0.5n² 是 50 亿，而 0.5n 只有 5 万，可以忽略；前面的系数 0.5 也不重要，因为它不改变「n 扩大 10 倍，次数扩大 100 倍」这个增长趋势。所以我们说这个算法的**时间复杂度是 O(n²)**。

### 2.2 大 O 的规则

**大 O 表示法**描述的是：当 n 趋向于无穷大时，操作次数的**增长量级**。计算方法：

1. 数出基本操作的执行次数，表示为 n 的函数；
2. **只保留增长最快的那一项**；
3. **去掉这一项的系数**。

| 操作次数 | 时间复杂度 |
|---|---|
| 3n + 100 | O(n) |
| 0.5n² - 0.5n | O(n²) |
| 2n² + 1000n log n | O(n²) |
| 5 log n + 20 | O(log n) |
| 1000（与 n 无关） | O(1) |

### 2.3 从代码判断复杂度

大多数时候不需要精确地数次数，看代码的结构就能判断：

```c
// O(1)：执行次数与 n 无关
int x = a[n / 2];

// O(n)：一层循环，循环 n 次
for (int i = 0; i < n; ++i) sum += a[i];

// O(n²)：两层嵌套循环，各 n 次
for (int i = 0; i < n; ++i)
    for (int j = 0; j < n; ++j) ...

// O(log n)：每次把范围缩小一半
for (int i = n; i > 1; i /= 2) ...

// O(n log n)：外层 n 次，内层每次 log n 次
for (int i = 0; i < n; ++i)
    for (int j = n; j > 1; j /= 2) ...
```

为什么「每次减半」是 O(log n)？从 n 开始不断除以 2，除到 1 为止，需要除 log₂n 次。比如 1024 只需要除 10 次，100 万只需要除 20 次。（在大 O 中，对数的底数不重要，因为不同底数的对数只差一个常数倍，所以直接写 log n。）

几个注意点：

- **顺序执行的几段代码，复杂度取最大的那一段**：一个 O(n) 的循环后面跟一个 O(n²) 的循环，整体是 O(n²)。
- **嵌套的复杂度要相乘**：外层 O(n)，内层 O(log n)，整体 O(n log n)。
- **调用的函数也要算进去**：循环 n 次，每次调用一个 O(n) 的函数（比如 `strlen`），整体是 O(n²)。这是一个常见的隐藏陷阱：`for (i = 0; i < strlen(s); ++i)` 每次判断条件时都会重新计算长度。

## 3. 常见的复杂度

| 复杂度 | 名称 | n = 10 | n = 1000 | n = 100 万 | 典型例子 |
|---|---|---|---|---|---|
| O(1) | 常数 | 1 | 1 | 1 | 数组下标访问、哈希表查找（平均） |
| O(log n) | 对数 | 3 | 10 | 20 | 二分查找、平衡树查找 |
| O(n) | 线性 | 10 | 1000 | 100 万 | 遍历数组、顺序查找 |
| O(n log n) | 线性对数 | 33 | 1 万 | 2000 万 | 快速排序、归并排序 |
| O(n²) | 平方 | 100 | 100 万 | 1 万亿 | 冒泡排序、两两比较 |
| O(2ⁿ) | 指数 | 1024 | 天文数字 | 天文数字 | 递归求斐波那契数（《函数》） |

（表中是大致的操作次数，log 以 2 为底。）

假设计算机每秒执行 10 亿次操作，n = 100 万时：O(n log n) 大约需要 0.02 秒，O(n²) 需要大约 17 分钟，而 O(2ⁿ) 即使宇宙毁灭也算不完。**当数据量大时，算法的复杂度比机器的快慢重要得多。**

### 3.1 实测

用第 1 节的两种方法查重，再加上顺序查找和二分查找，统计每种方法的比较次数，并测量查重所用的时间（`-O2` 编译，最坏情况：要查找的数不存在，数组中没有重复的元素）：

```c
static long long cmps = 0;                       // 比较次数

int linearSearch(const int* a, int n, int key)   // O(n)
{
    for (int i = 0; i < n; ++i) {
        ++cmps;
        if (a[i] == key) return i;
    }
    return -1;
}

int binarySearch(const int* a, int n, int key)   // O(log n)
{
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        ++cmps;
        if (a[mid] == key) return mid;
        if (a[mid] < key) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

int hasDupSort(int* a, int n)                    // O(n log n)
{
    qsort(a, n, sizeof(int), cmpInt);            // cmpInt 中也会 ++cmps
    for (int i = 1; i < n; ++i) {
        ++cmps;
        if (a[i] == a[i - 1]) return 1;
    }
    return 0;
}
```

结果：

| n | 二分查找 | 顺序查找 | 排序后查重 | 两两比较查重 |
|---|---|---|---|---|
| 1000 | 9 次 | 1000 次 | 10526 次，0.1 ms | 499500 次，0.5 ms |
| 1 万 | 13 次 | 1 万次 | 14 万次，1.6 ms | 5000 万次，24.6 ms |
| 10 万 | 16 次 | 10 万次 | 178 万次，8.6 ms | **50 亿次，1067 ms** |

- n 每扩大 10 倍：二分查找只多比较 3～4 次；顺序查找多 10 倍；两两比较多 **100 倍**。这正是 O(log n)、O(n)、O(n²) 的含义。
- n = 1000 时，两两比较只用了 0.5 毫秒，完全感觉不到慢。**复杂度的差距在数据量小的时候看不出来**，这正是它危险的地方：测试时一切正常，上线后数据一多，程序就卡死了。按照 O(n²) 推算，n = 100 万时两两比较需要大约 100 秒，而排序后查重只需要 0.1 秒左右。

## 4. 最好、最坏和平均情况

同一个算法，对不同的输入，操作次数可能不同。顺序查找：

- **最好情况**：第一个元素就是要找的，比较 1 次，O(1)；
- **最坏情况**：要找的元素在最后，或者根本不存在，比较 n 次，O(n)；
- **平均情况**：假设要找的元素等可能地出现在每个位置，平均比较 n/2 次，仍然是 O(n)。

**通常所说的复杂度指的是最坏情况**，因为它给出了一个保证：无论输入是什么，都不会比这更慢。最好情况几乎没有参考价值。有些算法的平均情况和最坏情况差别很大，比如快速排序平均 O(n log n)、最坏 O(n²)，这时两者都要说明（第 5 章会实测快速排序的最坏情况）。

还有一种**均摊分析**：一系列操作中，个别操作很慢，但平均到每一次操作上很快。比如动态数组的 `push_back`，偶尔扩容要复制所有元素，是 O(n) 的，但平均下来每次只需要 O(1)。下一篇《顺序表》会详细分析和实测。

## 5. 空间复杂度

**空间复杂度**衡量算法需要的**额外**内存随 n 增长的趋势（不算输入数据本身占用的空间）：

```c
// O(1) 空间：只用了几个变量
long long sum(const int* a, int n)
{
    long long s = 0;
    for (int i = 0; i < n; ++i) s += a[i];
    return s;
}

// O(n) 空间：申请了一个和输入一样大的数组
int* copyReversed(const int* a, int n)
{
    int* b = malloc(n * sizeof(int));
    for (int i = 0; i < n; ++i) b[i] = a[n - 1 - i];
    return b;
}

// O(n) 空间：递归深度为 n，每一层占一个栈帧
long long sumTo(int n) { return n == 0 ? 0 : n + sumTo(n - 1); }
```

注意最后一个例子：它没有申请任何数组，但**递归的每一层都占用一个栈帧**，递归深度是 n，所以空间复杂度是 O(n)。《函数》中，`sumTo(10000000)` 就因为递归太深导致了栈溢出。

很多时候，时间和空间可以互相交换：多用一些内存记住中间结果，就可以少做一些重复的计算（「以空间换时间」）。比如递归的斐波那契是 O(2ⁿ) 的时间，用一个数组保存已经算过的结果，就变成了 O(n) 的时间和 O(n) 的空间。

## 6. 常见错误

1. **只在小数据上测试性能**：O(n²) 的算法在 n = 1000 时也很快。
2. **保留系数和低次项**：O(2n + 3) 应该写成 O(n)。
3. **忽略循环中调用的函数的复杂度**：比如在循环条件中调用 `strlen`。
4. **把最好情况当作算法的复杂度**。
5. **忘记递归调用栈占用的空间**。
6. **认为复杂度低的算法一定更快**：O(n log n) 的算法常数可能很大，在 n 很小时反而比 O(n²) 慢。所以标准库的排序在元素很少时会改用插入排序。

## 7. 小结

- 复杂度描述的是操作次数随规模 n 增长的趋势，与机器无关
- 大 O 表示法：只保留增长最快的项，去掉系数
- 常见复杂度从低到高：O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)
- 实测：n 从 1000 增加到 10 万，两两比较查重的比较次数从 50 万增加到 50 亿，二分查找只从 9 次增加到 16 次
- 通常关注最坏情况；均摊分析把偶尔的高代价平均到每次操作上
- 空间复杂度衡量额外使用的内存，包括递归调用栈

## 8. 练习

1. 写出下面各段代码的时间复杂度：

   ```c
   // (a)
   for (int i = 0; i < n; i += 2) ...
   // (b)
   for (int i = 1; i < n; i *= 3) ...
   // (c)
   for (int i = 0; i < n; ++i)
       for (int j = 0; j < i; ++j) ...
   // (d)
   for (int i = 0; i < n; ++i) ...
   for (int j = 0; j < m; ++j) ...
   // (e)
   for (int i = 0; i < 100; ++i)
       for (int j = 0; j < n; ++j) ...
   ```

2. 一个 O(n²) 的算法处理 1 万个数据用了 0.1 秒，处理 10 万个数据大约要多久？如果是 O(n log n) 的算法呢？
3. 下面的函数的时间复杂度是多少？怎样优化？

   ```c
   int countUpper(const char* s)
   {
       int count = 0;
       for (size_t i = 0; i < strlen(s); ++i)
           if (s[i] >= 'A' && s[i] <= 'Z') ++count;
       return count;
   }
   ```

<details>
<summary>点击查看答案</summary>

1. (a) O(n)，循环 n/2 次，去掉系数；(b) O(log n)，每次乘以 3，循环 log₃n 次；(c) O(n²)，内层循环一共执行 0 + 1 + … + (n-1) = n(n-1)/2 次；(d) O(n + m)，两个独立的规模不能合并；(e) O(n)，外层的 100 是常数。

2. O(n²)：n 扩大 10 倍，时间扩大 100 倍，大约 10 秒。O(n log n)：时间扩大 10 × log(10 万) / log(1 万) ≈ 10 × 16.6 / 13.3 ≈ 12.5 倍，大约 1.25 秒（如果它在 1 万个数据上也是 0.1 秒的话）。

3. `strlen` 本身是 O(n) 的，而它在每次判断循环条件时都会被调用一次，所以整体是 O(n²)。把长度提前算好：

   ```c
   size_t len = strlen(s);
   for (size_t i = 0; i < len; ++i) ...
   ```

   或者直接用 `for (size_t i = 0; s[i] != '\0'; ++i)`，都变成了 O(n)。

</details>

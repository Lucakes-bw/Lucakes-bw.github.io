> **本文目标**：理解比较排序的下界；会实现计数排序和基数排序，知道它们的适用条件；能根据实测数据和场景选择合适的排序算法。
>
> **前置知识**：《简单排序》、《快速排序与归并排序》、《堆与优先队列》（堆排序）。

## 1. 比较排序的下界

到目前为止的所有排序，都是通过**比较两个元素的大小**来决定它们的顺序的。可以证明，任何基于比较的排序，最坏情况下都至少需要 **log₂(n!) ≈ n log₂n** 次比较。

简单的理解是：n 个元素有 n! 种可能的排列，排序就是要确定是其中的哪一种。每次比较只有两种结果，最多把可能性排除一半，所以至少需要 log₂(n!) 次比较。而 log₂(n!) 和 n log₂n 是同一个量级。

所以归并排序、堆排序已经是最优的比较排序了。要更快，就必须**不通过比较**来排序，这需要利用数据本身的特点。

## 2. 计数排序

如果所有的数都是 0 到 k - 1 之间的整数，而且 k 不太大，那么可以直接**数一数每个值出现了几次**：

```c
void countingSort(int* a, int n, int k)
{
    int* count = calloc(k, sizeof(int));
    int* out = malloc(n * sizeof(int));
    if (!count || !out) exit(1);
    for (int i = 0; i < n; ++i) count[a[i]]++;             // 统计每个值出现的次数
    for (int v = 1; v < k; ++v) count[v] += count[v - 1];  // 前缀和：count[v] = 小于等于 v 的个数
    for (int i = n - 1; i >= 0; --i) out[--count[a[i]]] = a[i];   // 从后往前放，保证稳定
    memcpy(a, out, n * sizeof(int));
    free(count); free(out);
}
```

三个步骤：

1. **计数**：`count[v]` 是值 v 出现的次数；
2. **前缀和**：之后 `count[v]` 变成「小于等于 v 的元素有几个」，也就是值为 v 的最后一个元素在输出中的位置（的下一个）；
3. **放置**：**从后往前**扫描输入，每个元素放到 `--count[a[i]]` 的位置。从后往前是为了让值相同的元素保持原来的顺序，即**稳定**。

如果只是排序整数，第 3 步可以直接按 count 输出 v 个 v；但上面的写法也能用于排序带有其他数据的记录（比如按年龄排序学生），这时稳定性就很重要了。

计数排序的时间复杂度是 **O(n + k)**，空间也是 O(n + k)。它适合**值的范围小、数据量大**的情况，比如对 100 万个人按年龄（0 到 150）排序、对考试成绩（0 到 100）排序。如果值的范围很大（比如任意的 32 位整数），`count` 数组就大得无法接受了。

## 3. 基数排序

基数排序解决了值的范围大的问题：把每个数拆成几「位」，**从最低位到最高位，每一位做一次稳定的计数排序**。下面把 32 位整数拆成 4 个字节，每个字节的范围只有 0 到 255：

```c
void radixSort(unsigned* a, int n)
{
    unsigned* out = malloc(n * sizeof(unsigned));
    if (!out) exit(1);
    for (int shift = 0; shift < 32; shift += 8) {
        int count[257] = {0};
        for (int i = 0; i < n; ++i) count[((a[i] >> shift) & 0xFF) + 1]++;
        for (int b = 0; b < 256; ++b) count[b + 1] += count[b];   // count[b] = 这一位小于 b 的个数
        for (int i = 0; i < n; ++i) out[count[(a[i] >> shift) & 0xFF]++] = a[i];   // 稳定
        memcpy(a, out, n * sizeof(unsigned));
    }
    free(out);
}
```

（这里的计数排序写法稍有不同：`count[b]` 是「小于 b 的个数」，即值为 b 的**第一个**元素的位置，然后从前往后放，同样是稳定的。）

为什么从低位开始、而且每一位必须稳定？以十进制的三位数为例：

```
原始    按个位    按十位    按百位
329     720      720      329
457     355      329      355
657     436      436      436
839     457      839      457
436     657      355      657
720     329      457      720
355     839      657      839
```

按十位排序时，十位相同的 720 和 329（都是 2），由于稳定性，保持了按个位排好的顺序。最后按百位排完，前面几位的顺序都被保留了下来。实测程序对这组数的结果：

```
基数排序: 329 355 436 457 657 720 839
```

基数排序的时间复杂度是 **O(d × (n + b))**，d 是位数（这里是 4），b 是每一位的范围（256）。对于固定长度的整数，就是 O(n)。

## 4. 排序算法实测汇总

把本章的 9 种排序放在一起，对 0 到 999999 之间的随机整数排序（`-O2`），每个结果都检查过确实排好了序：

```
                           10000        100000       1000000
冒泡排序             40.7 ms     2013.2 ms             -
选择排序             69.9 ms     4211.2 ms             -
插入排序              5.6 ms      665.5 ms             -
堆排序                 0.3 ms        4.3 ms       60.5 ms
归并排序              0.3 ms        3.2 ms       40.0 ms
快速排序（改进）        0.4 ms        3.6 ms       41.8 ms
qsort                     0.4 ms        4.6 ms       56.0 ms
计数排序              0.3 ms        0.4 ms        2.4 ms
基数排序              0.0 ms        0.4 ms        4.1 ms
```

（O(n²) 的三种排序没有测 100 万个数据，按 10 万个数据的结果推算，冒泡排序要 3 分钟以上，选择排序要 7 分钟左右。）

- **O(n²) 和 O(n log n) 的差距随 n 迅速拉大**：10 万个数据时，插入排序用了 666 毫秒，归并排序只用了 3.2 毫秒，相差 200 倍。
- **三种 O(n log n) 的排序中**，归并排序和改进的快速排序差不多，堆排序最慢（缓存不友好，见上一篇的练习 3）。
- **计数排序和基数排序最快**，100 万个数据只用了 2～4 毫秒，比快速排序快 10 倍以上。
- 注意 n = 1 万时计数排序并不快：值的范围 k = 100 万，O(n + k) 中 k 占了主导，光是清零和扫描 `count` 数组就要 100 万次操作。

## 5. 如何选择排序算法

| 排序 | 平均 | 最坏 | 额外空间 | 稳定 | 适用场景 |
|---|---|---|---|---|---|
| 冒泡排序 | O(n²) | O(n²) | O(1) | 是 | 教学 |
| 选择排序 | O(n²) | O(n²) | O(1) | 否 | 交换代价很高时 |
| 插入排序 | O(n²) | O(n²) | O(1) | 是 | 数据量小、基本有序 |
| 堆排序 | O(n log n) | O(n log n) | O(1) | 否 | 需要最坏情况保证、内存紧张 |
| 归并排序 | O(n log n) | O(n log n) | O(n) | 是 | 需要稳定、链表、外部排序 |
| 快速排序 | O(n log n) | O(n²) | O(log n) | 否 | 通用，实际最快的比较排序 |
| 计数排序 | O(n + k) | O(n + k) | O(n + k) | 是 | 整数，值的范围 k 小 |
| 基数排序 | O(d(n + b)) | O(d(n + b)) | O(n + b) | 是 | 固定长度的整数、字符串 |

实际编程中的建议：

1. **首先使用标准库**：C 的 `qsort`，C++ 的 `std::sort`（不稳定）和 `std::stable_sort`（稳定）。它们经过了充分的优化和测试。
2. 数据量很小（几十个以内）或者基本有序：插入排序。
3. 要求稳定：归并排序（`std::stable_sort`）。
4. 大量的整数，值的范围有限：计数排序或基数排序。
5. 只需要前 k 个，而不需要全部排序：用堆（《堆与优先队列》的 Top K）或快速选择（上一篇的练习 1）。

所有的程序都用 `-fsanitize=address,undefined` 检查过。

## 6. 常见错误

1. **对值的范围很大的数据用计数排序**：`count` 数组太大，比排序本身还慢，甚至分配不出内存。
2. **计数排序处理负数**：下标为负，越界。要先减去最小值。
3. **基数排序中每一位的排序不稳定**：前面几位的顺序被打乱，结果错误。
4. **基数排序直接处理有符号整数**：负数的补码最高位是 1，按无符号比较会排到最后。要先把符号位翻转。
5. **自己实现排序而不用标准库**：除非有特殊的需求，标准库通常更快、更可靠。

## 7. 小结

- 基于比较的排序最坏至少需要约 n log n 次比较，归并排序和堆排序已经是最优的
- 计数排序统计每个值的次数，O(n + k)，适合值的范围小的整数
- 基数排序从低位到高位做稳定的计数排序，对固定长度的整数是 O(n)
- 实测 100 万个整数：计数排序 2.4 ms，基数排序 4.1 ms，快速排序 42 ms，堆排序 61 ms；O(n²) 的排序在 10 万个数据时就要 0.7～4 秒
- 优先使用标准库；根据数据量、是否有序、是否需要稳定、值的范围来选择

## 8. 练习

1. 一个文件中有 1 亿条记录，每条记录有一个 0 到 150 之间的年龄。要按年龄排序，并且年龄相同的记录保持原来的顺序，用什么方法？
2. 基数排序中，如果从最高位开始、而不是从最低位开始排序，直接这样做为什么不对？
3. 如果要对 100 万个字符串（每个最长 20 个字符）排序，可以用什么方法？

<details>

1. 计数排序：k = 151，非常小，时间 O(n)，而且是稳定的。如果记录太多放不进内存，可以扫描两遍文件：第一遍只统计每个年龄的个数，算出前缀和；第二遍把每条记录写到输出文件中对应的位置。

2. 先按最高位排好之后，再按次高位排序时，会把最高位不同的数混在一起重新排列，最高位的顺序就被打乱了。要从最高位开始，就必须先按最高位分成若干个桶，然后在**每个桶内部**递归地按次高位排序（MSD 基数排序），而不能对整个数组按次高位排序。

3. 可以用基数排序：把字符串看作最多 20 位的「数」，每一位是一个字节，从最后一个字符开始（短的字符串在末尾补一个比所有字符都小的值）。不过对字符串，更常用的是 MSD 基数排序或者直接用快速排序（`qsort` 加上 `strcmp`），因为很多字符串在前几个字符就能区分开，不需要比较全部 20 个字符。

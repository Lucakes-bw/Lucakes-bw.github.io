## 1. 优先队列

普通的队列先进先出。但很多时候，我们希望**优先级最高的先出来**：操作系统优先运行重要的进程；急诊室优先处理病情最重的病人；第 4 章的 Dijkstra 最短路径算法每次要取出距离最小的节点。这种数据结构叫**优先队列**，它需要两个操作：插入一个元素、取出最大（或最小）的元素。

用什么实现？

| 实现 | 插入 | 取出最大值 |
|---|---|---|
| 无序数组 | O(1) | O(n)，要找一遍 |
| 有序数组 | O(n)，要移动元素 | O(1) |
| 平衡二叉搜索树 | O(log n) | O(log n) |
| **堆** | O(log n) | O(log n) |

堆和平衡树的复杂度一样，但堆**用数组存储，不需要指针，实现简单得多**，常数也更小。

## 2. 堆

**大顶堆**是满足下面两个条件的二叉树：

1. 它是一棵**完全二叉树**：除了最后一层都是满的，最后一层的节点靠左排列；
2. **每个节点都不小于它的孩子**。

于是根节点（堆顶）就是最大值。（每个节点都不大于孩子的叫**小顶堆**，堆顶是最小值。）

注意堆和二叉搜索树不同：堆只要求父节点比孩子大，**左右孩子之间没有大小关系**，所以堆不能用来快速查找任意一个值。

完全二叉树可以直接存放在数组中（《二叉树与遍历》第 2.1 节）：下标为 i 的节点，左孩子是 2i + 1，右孩子是 2i + 2，父节点是 (i - 1) / 2。

```c
typedef struct {
    int* data;
    size_t size;
    size_t capacity;
} Heap;                                         // 大顶堆：父节点不小于孩子
```

## 3. 上浮和下沉

堆的所有操作都基于两个基本动作。

**上浮**（sift up）：某个元素比父节点大，就和父节点交换，一直到它不比父节点大或者到达堆顶：

```c
static void siftUp(int* a, size_t i)
{
    while (i > 0) {
        size_t parent = (i - 1) / 2;
        if (a[parent] >= a[i]) break;           // 父节点更大，已经满足堆的性质
        swap(&a[parent], &a[i]);
        i = parent;
    }
}
```

**下沉**（sift down）：某个元素比孩子小，就和**较大的那个孩子**交换，一直到它不小于两个孩子或者成为叶子：

```c
static void siftDown(int* a, size_t n, size_t i)
{
    for (;;) {
        size_t left = 2 * i + 1, right = left + 1, largest = i;
        if (left < n && a[left] > a[largest]) largest = left;
        if (right < n && a[right] > a[largest]) largest = right;
        if (largest == i) break;                // 比两个孩子都大，停止
        swap(&a[i], &a[largest]);
        i = largest;
    }
}
```

为什么要和**较大的**孩子交换？因为交换后它会成为另一个孩子的父节点，必须比另一个孩子大。

上浮和下沉每次移动一层，最多移动树的高度那么多次，而完全二叉树的高度是 log n，所以都是 **O(log n)**。

## 4. 插入和取出

**插入**：把新元素放在数组的最后（这样仍然是完全二叉树），然后上浮。

**取出最大值**：堆顶就是最大值。取出后，把**最后一个元素**移到堆顶（仍然是完全二叉树），然后下沉。

```c
int heapPush(Heap* h, int value)
{
    if (h->size == h->capacity) {
        size_t cap = h->capacity ? h->capacity * 2 : 8;
        int* p = realloc(h->data, cap * sizeof(int));
        if (p == NULL) return 0;
        h->data = p;
        h->capacity = cap;
    }
    h->data[h->size] = value;                   // 放在最后
    siftUp(h->data, h->size);                   // 上浮
    h->size++;
    return 1;
}

int heapPop(Heap* h, int* out)
{
    if (h->size == 0) return 0;
    *out = h->data[0];                          // 堆顶是最大值
    h->data[0] = h->data[--h->size];            // 最后一个元素移到堆顶
    siftDown(h->data, h->size, 0);              // 下沉
    return 1;
}
```

在演示中，上方是树的视图，下方是数组的视图，它们是**同一份数据**：交换两个元素时，树中的两个节点和数组中的两个格子同时改变。试试入堆和出堆，以及最后一个按钮的 heapify：

```c
Heap h = {NULL, 0, 0};
int vals[] = {30, 10, 50, 20, 40, 60, 5};
for (int i = 0; i < 7; ++i) heapPush(&h, vals[i]);
printf("数组:"); for (size_t i = 0; i < h.size; ++i) printf(" %d", h.data[i]); printf("\n");

```

依次出堆的结果是从大到小排列的，这就是堆排序的思路。

## 5. 建堆：heapify

已经有了一个数组，怎样把它变成堆？逐个插入是 O(n log n) 的。更好的方法是 **heapify**：叶子节点自己就是合法的堆，所以**从最后一个非叶子节点开始，倒着对每个节点做下沉**。处理到节点 i 时，它的两棵子树都已经是堆了，下沉之后以 i 为根的子树也成了堆。

```c
void heapify(int* a, size_t n)                  // O(n) 建堆
{
    for (size_t i = n / 2; i-- > 0; ) {         // 从最后一个非叶子节点开始，倒着下沉
        siftDown(a, n, i);
    }
}
```

（`for (size_t i = n / 2; i-- > 0; )` 是倒序遍历无符号下标的安全写法：先判断再减 1，i 依次取 n/2 - 1, …, 0。写成 `for (size_t i = n / 2 - 1; i >= 0; --i)` 就是《流程控制》中的无符号死循环。）

为什么是 O(n)？下沉的次数取决于节点的**高度**，而不是深度。完全二叉树中一半的节点是叶子，不需要下沉；四分之一的节点最多下沉 1 层；八分之一的节点最多下沉 2 层……总和是 n/4 × 1 + n/8 × 2 + n/16 × 3 + … < n。而逐个插入时，上浮的次数取决于深度，大部分节点都在下面几层，最坏需要上浮 log n 层。

实测：用递增的数据（逐个插入的最坏情况，每个新元素都要上浮到堆顶），统计交换的次数：

```
n = 100000   逐个插入建堆交换 1468946 次，heapify 交换 99990 次
n = 1000000  逐个插入建堆交换 17951445 次，heapify 交换 999988 次
```

100 万个数据时，逐个插入交换了约 1795 万次（约 n log n 的量级），heapify 只交换了约 100 万次（不到 n）。（如果数据是随机的，逐个插入平均只需要上浮很少几层，实测 100 万个随机数交换了 128 万次，heapify 是 74 万次，差距没有这么大。）

## 6. 堆排序

有了 heapify 和下沉，排序就很简单了：先建成大顶堆，然后反复把堆顶（最大值）和堆的最后一个元素交换，堆的大小减 1，再对新的堆顶下沉。最大值依次被放到了数组的末尾：

```c
void heapSort(int* a, size_t n)
{
    heapify(a, n);
    for (size_t end = n; end > 1; --end) {
        swap(&a[0], &a[end - 1]);               // 把最大值放到末尾
        siftDown(a, end - 1, 0);                // 剩下的重新调整成堆
    }
}
```

```
heapify: 10 5 9 4 1 8 3 2
heapSort: 1 2 3 4 5 8 9 10
```

堆排序的时间复杂度是 O(n log n)，而且**最坏情况也是 O(n log n)**，只需要 O(1) 的额外空间。缺点是它不稳定，而且访问内存的跳跃很大，对缓存不友好，实际中通常比快速排序慢。第 5 章会把它和其他排序算法放在一起比较。

## 7. Top K 问题

在 100 万个数中找最大的 10 个。最直接的方法是全部排序，取前 10 个，O(n log n)。

更好的方法是维护一个**大小为 k 的小顶堆**，保存「目前为止最大的 k 个数」：堆顶是这 k 个中最小的。对每个新的数，如果比堆顶大，就替换堆顶并下沉。最后堆中就是最大的 k 个数。

```c
// 在 n 个数中找最大的 k 个：维护一个大小为 k 的小顶堆（存相反数，用大顶堆代码实现）
void topK(const int* a, size_t n, int* out, size_t k)
{
    size_t size = 0;
    for (size_t i = 0; i < n; ++i) {
        if (size < k) {
            out[size] = -a[i];
            siftUp(out, size);
            size++;
        } else if (a[i] > -out[0]) {            // 比堆中最小的还大，替换它
            out[0] = -a[i];
            siftDown(out, k, 0);
        }
    }
    for (size_t i = 0; i < size; ++i) out[i] = -out[i];
}
```

（这里用了一个小技巧：把所有数取相反数存进大顶堆，就相当于一个小顶堆，可以复用前面的代码。实际使用时要注意 `INT_MIN` 取相反数会溢出。）

时间复杂度是 O(n log k)，空间只需要 O(k)。实测（随机数据，`-O2`），并检查和排序的结果一致：

```
n = 100000   最大的 10 个：堆 0.13 ms，全部排序 11.6 ms，结果一致
n = 1000000  最大的 10 个：堆 0.76 ms，全部排序 64.2 ms，结果一致
```

100 万个数据时快了 80 多倍。而且这个方法不需要把所有数据同时放在内存中，数据可以一个一个地读入，适合处理**数据流**或者**超大的文件**。

所有的程序都用 `-fsanitize=address,undefined` 和 `leaks` 检查过。

## 8. C++ 中的优先队列

C++ 的 `std::priority_queue`（《STL 容器》）就是用堆实现的，默认是大顶堆：

```cpp
std::priority_queue<int> maxHeap;                                       // 大顶堆
std::priority_queue<int, std::vector<int>, std::greater<int>> minHeap;   // 小顶堆
maxHeap.push(3);
int top = maxHeap.top();    // 查看最大值
maxHeap.pop();              // 删除最大值（不返回）
```

`<algorithm>` 中还有 `std::make_heap`、`std::push_heap`、`std::pop_heap`，可以直接在一个 `vector` 上执行堆操作。

## 9. 常见错误

1. **下沉时和任意一个比它大的孩子交换**：必须和较大的孩子交换，否则另一个孩子可能比新的父节点大。
2. **下标公式写错**：从 0 开始时孩子是 2i+1 和 2i+2，父节点是 (i-1)/2；从 1 开始时是 2i、2i+1 和 i/2，不能混用。
3. **下沉时没有检查孩子是否存在**：越界访问。
4. **heapify 从下标 0 正着做下沉**：此时子树还不是堆，结果不正确。
5. **倒序循环用无符号下标 `i >= 0`**：死循环。
6. **以为堆是有序的**：只有堆顶是最大值，其余元素之间没有完整的顺序。
7. **Top K 问题用大顶堆**：找最大的 k 个要用小顶堆，这样才能快速知道 k 个中最小的、决定是否替换。

## 10. 小结

- 堆是完全二叉树，用数组存储；大顶堆中每个节点不小于孩子，堆顶是最大值
- 插入：放在最后，上浮；取出：最后一个元素移到堆顶，下沉；都是 O(log n)
- heapify 从最后一个非叶子节点开始倒着下沉，O(n)；实测递增数据时交换次数只有逐个插入的约 1/18
- 堆排序最坏也是 O(n log n)，O(1) 额外空间，但不稳定
- Top K 用大小为 k 的小顶堆，O(n log k)，实测比全部排序快 80 多倍

2. 对数组 `{4, 10, 3, 5, 1, 8, 9, 2}` 执行 heapify，写出每次下沉之后的数组。
3. 怎样用两个堆，在数据不断到来的过程中随时得到所有数据的**中位数**？

   和程序的输出一致。

3. 用一个**大顶堆**保存较小的一半数据，一个**小顶堆**保存较大的一半，并保持两个堆的大小相差不超过 1。新数据比大顶堆的堆顶小就放进大顶堆，否则放进小顶堆，然后把多出来的那个堆的堆顶移到另一个堆中。中位数就是较大的那个堆的堆顶（两个堆一样大时取两个堆顶的平均值）。每次插入 O(log n)，查询 O(1)。

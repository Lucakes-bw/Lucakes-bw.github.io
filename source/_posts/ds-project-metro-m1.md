> **本文目标**：实现一个字符串到整数的哈希表；设计地铁图的存储结构，用邻接表保存车站之间的区间；逐行解析数据文件，并给出准确的错误信息；不泄漏内存。
>
> **前置知识**：《哈希表》、《图的表示与遍历》（邻接表）、《顺序表》（动态数组的扩容）。还没有下载起始代码的话，先看[项目总览](/posts/ds-project-metro/)。

## 1. 要做什么

完成这个里程碑后，程序可以回答三种问题。下面是参考实现的实际输出。

**`stats`：统计**

```
metro> stats
线路 4 条，车站 22 个，区间 25 个，换乘站 7 个
```

区间是相邻两站之间的一段；换乘站是有两条或更多线路经过的车站。

**`line <线路名>`：按顺序列出一条线路**

```
metro> line 2号线
2号线：共 7 站，全程 17 分钟
北站 -3- 体育馆 -2- 文化宫 -3- 人民广场 -2- 南湖 -3- 大学城 -4- 南站
```

**`station <站名>`：车站所在的线路，以及每条线路上相邻的车站**

```
metro> station 人民广场
人民广场：1号线、2号线（换乘站）
  1号线：动物园 3 分钟、市政府 2 分钟
  2号线：文化宫 3 分钟、南湖 2 分钟
metro> station 西山
西山：1号线
  1号线：果园 3 分钟
```

这些输出都由已经写好的 `main.c` 完成，它只读取 `Metro` 结构体中的数据。你的任务是**把数据文件正确地读进 `Metro` 结构体**。只要结构体中的数据对了，输出自然就对了。

## 2. 数据文件

### 2.1 格式

```
# 以 # 开头的行是注释，空行会被忽略
LINE 1号线
西山
果园 3
动物园 2
END
```

- `LINE <线路名>` 开始一条线路，`END` 结束这条线路；
- 中间每一行是一个车站，按顺序排列。首站只写站名；后面的每一站写站名和**从上一站开过来的分钟数**；
- 一行中的各项用空格或 Tab 分隔，站名和线路名中没有空格；
- 一个车站可以出现在多条线路中，这就是换乘站。

文件可能是在 Windows 中编辑的，行末会多出一个 `\r`，也要能正确处理。

### 2.2 要检查的错误

数据文件是人写的，难免出错。遇到错误时，`metroLoad` 返回 -1，并把错误信息写到 `err` 中，`main` 会把它输出到标准错误，然后退出。错误信息要**和下表完全一致**（测试会逐字比较）：

| 情况 | 错误信息 |
|---|---|
| 文件打不开 | `无法打开文件：<路径>`（起始代码已经写好） |
| `LINE` 后面没有线路名 | `数据错误（第 N 行）：LINE 后面缺少线路名` |
| 线路名和前面的重复 | `数据错误（第 N 行）：线路重复：<线路名>` |
| 上一条线路还没有 `END`，又出现了 `LINE` | `数据错误（第 N 行）：线路 <线路名> 缺少 END` |
| 文件结束时，最后一条线路还没有 `END` | `数据错误：线路 <线路名> 缺少 END` |
| 不在任何 `LINE` 中的 `END` | `数据错误（第 N 行）：END 前面没有 LINE` |
| 一条线路少于 2 个车站 | `数据错误（第 N 行）：线路 <线路名> 至少要有 2 个车站` |
| 不在任何线路中的车站 | `数据错误（第 N 行）：车站 <站名> 不在任何线路中` |
| 首站写了分钟数 | `数据错误（第 N 行）：首站 <站名> 不能有运行时间` |
| 不是首站，但没有写分钟数 | `数据错误（第 N 行）：车站 <站名> 缺少运行时间` |
| 分钟数不是正整数（比如 `0`、`3分钟`） | `数据错误（第 N 行）：运行时间必须是正整数：<写的内容>` |
| 同一个车站在一条线路中出现两次 | `数据错误（第 N 行）：车站 <站名> 在线路 <线路名> 中重复` |
| 一行中多出了内容 | `数据错误（第 N 行）：多余的内容：<第一个多余的部分>` |
| 文件中一条线路都没有 | `数据错误：没有任何线路` |

N 是出错的那一行的行号，从 1 开始，注释和空行也要计数。起始代码中的 `loadError` 函数已经帮你拼好了「数据错误（第 N 行）：」这个开头，你只需要写后面的部分：

```c
return loadError(err, errSize, lineno, "车站 %s 缺少运行时间", name);
```

一行中可能同时有好几个错误，比如 `乙 2 3` 是多余的内容，`乙 0 3` 既有多余的内容、分钟数又是 0。为了让结果确定，**按下面的顺序检查，报告第一个错误**：

- `LINE` 行：缺少 END → 缺少线路名 → 多余的内容 → 线路重复
- `END` 行：前面没有 LINE → 多余的内容 → 少于 2 个车站
- 车站行：不在任何线路中 → 多余的内容 → 首站有运行时间 / 缺少运行时间 / 运行时间不是正整数 → 车站重复

## 3. 设计存储结构

动手写代码之前，先看一下 `metro.h` 中已经定义好的结构，想清楚为什么要这样设计。

### 3.1 车站用编号表示

```c
typedef struct {
    Station* stations;              // 车站的编号就是它在这个数组中的下标
    int nstations, capStations;
    Line* lines;                    // 线路的编号就是它在这个数组中的下标
    int nlines, capLines;
    int nsegments;                  // 区间的个数
    HashMap stationIndex;           // 站名 -> 车站编号
    HashMap lineIndex;              // 线路名 -> 线路编号
} Metro;
```

每个车站有一个**编号**，就是它在 `stations` 数组中的下标，按第一次在文件中出现的顺序分配：西山是 0，果园是 1……图中的边、线路中的车站，保存的都是编号而不是站名。

这样做有两个好处：

1. 后面的 BFS、Dijkstra 需要 `visited[v]`、`dist[v]` 这样的数组，只有用整数编号才能直接作下标；
2. 比较两个车站是否相同，比较整数比比较字符串快得多，也不用担心字符串被复制了好几份。

但用户输入的是站名，读取数据文件时遇到的也是站名，所以需要一个**站名 → 编号**的映射。车站只有 22 个，挨个比较也很快；但如果是一座有上千个车站的城市，读取数据时每遇到一个站名都要查一次，顺序查找就是 O(n²) 了。所以用**哈希表**，平均 O(1)。线路名也一样。

### 3.2 邻接表

```c
typedef struct {
    int to;                         // 相邻车站的编号
    int line;                       // 线路的编号
    int minutes;                    // 运行时间（分钟）
} Edge;

typedef struct {
    char* name;
    Edge* edges;                    // 邻接表，按添加的顺序保存
    int nedges, capEdges;
} Station;
```

和《最短路径》一文中的带权图相比，这里的边多了一个 `line`：同一对车站之间，可能有不止一条线路经过，而且后面计算换乘时，必须知道每一段是坐哪条线。

地铁可以双向行驶，所以每个区间是一条**无向边**，在两个车站的邻接表中各存一条有向边。`nsegments` 统计的是区间的个数，也就是无向边的条数。

邻接表用动态数组而不是链表：车站的邻居都是在读取数据时一次性加进去的，之后只读不改，数组更省内存，遍历也更快。

**添加的顺序很重要**。`main.c` 输出车站的相邻车站时，按邻接表中的顺序输出。如果你按读取的顺序**追加**到数组末尾，那么对于每一条线路，上一站会排在下一站前面，先出现的线路也会排在后面的线路前面，这正是测试期望的顺序。如果插到开头，顺序就反了。

### 3.3 线路

```c
typedef struct {
    char* name;
    int* stations;                  // 按顺序排列的车站编号
    int* minutes;                   // minutes[i]：从第 i-1 站到第 i 站的时间，minutes[0] = 0
    int nstations, capStations;
} Line;
```

线路的信息其实已经都在邻接表中了，但要从邻接表中按顺序还原一条线路很麻烦，所以单独保存一份。`stations` 和 `minutes` 的长度总是相同的，共用一个容量 `capStations`。

### 3.4 一次查询经过了哪些结构

把这几个结构串起来看。下面的演示用一个很小的数据文件（第 4.3 节会演示它是怎么读进来的）：A线 依次经过甲、乙、丙，B线 从丁到乙，乙是换乘站。程序执行 `station 乙` 时：

1. **站名 → 编号**：在 `stationIndex` 中查找。先算出「乙」的哈希值，对桶的个数 8 取余数，只在那一个桶的链表里比较字符串；
2. **编号 → 车站**：拿到编号 1 以后，直接用下标取出 `stations[1]`，不需要再比较任何字符串；
3. **车站 → 相邻车站**：遍历 `stations[1]` 的邻接表，按线路分组输出。

可以在下方输入其他站名试试，比如「丁」或者「人民广场」。丙和丁恰好落在同一个桶里，这就是哈希冲突：后插入的丁排在链表的前面。「人民广场」不在这份数据中，但它的哈希值也落在这个桶，所以要和丁、丙都比较一遍，才能确定找不到。演示中的哈希值和桶号，就是 C 程序中的 FNV-1a 实际算出来的。

### 4.1 哈希表

打开 `src/hashmap.c`，实现 4 个函数。这就是《哈希表》一文第 3 节的链地址法，只是值的类型是 `int`，并且 `hmGet` 找不到时返回 -1（车站和线路的编号都不小于 0，所以 -1 不会和正常的值混淆）。

要求：

- 哈希函数用 FNV-1a；
- `hmInit` 创建 8 个桶；元素个数超过桶的个数时，桶的个数翻倍，所有元素重新分配；
- `hmPut` 要**复制**一份键保存；键已经存在时，只更新值，不增加元素；
- `hmFree` 释放所有元素的键、元素本身和桶数组。

**检查点 1**：运行 `tests/run.sh m1 hash`，应该看到：

```
== 里程碑 1 · hash（哈希表）==
[通过] 哈希表：插入、查找和更新
[通过] 哈希表：键要复制一份保存
[通过] 哈希表：20 万个键：扩容和速度

hash 这一组全部通过：3/3
```

第 3 项会插入 20 万个键。如果哈希函数很差，或者忘记扩容，链表会变得很长，查找退化成顺序查找，3 秒内都完成不了，测试会提前停下来并报告失败。

<details>
<summary>提示：键为什么要复制</summary>

读取数据文件时，站名来自 `fgets` 读到的缓冲区 `buf`。读下一行时，`buf` 的内容会被覆盖。如果哈希表只保存了指针，之前插入的所有键都会变成最后一行的内容。测试中的「键要复制一份保存」检查的就是这个问题。

</details>

### 4.2 建图的几个小函数

在 `src/metro.c` 中，建议先写 3 个 `static` 函数：

```c
static int getOrAddStation(Metro* m, const char* name);    // 返回车站编号，不存在就新建
static int addLine(Metro* m, const char* name);            // 新建一条线路，返回编号
static void appendStation(Metro* m, int lineId, int s, int minutes);  // 车站加到线路末尾
```

`getOrAddStation` 先用 `stationIndex` 查找；找不到，就在 `stations` 数组末尾增加一个车站（复制名字，邻接表为空），再把「站名 → 新编号」放进 `stationIndex`。

`appendStation` 把车站编号和分钟数追加到线路的两个数组中。如果这不是线路的首站，就取出上一站的编号 `prev`，在 `prev` 和 `s` 的邻接表中各追加一条边，`nsegments` 加 1。

几个数组（`stations`、`lines`、每个车站的 `edges`、每条线路的 `stations` 和 `minutes`）都要在容量不够时扩容。和《顺序表》一样，用 `realloc` 把容量翻倍。可以写一个通用的函数，避免把同样的代码写 4 遍。

<details>
<summary>提示：一个通用的扩容函数</summary>

```c
// 保证数组 *a 至少能放下 need 个元素，容量不够时翻倍
static void reserve(void** a, int* cap, int need, size_t elemSize)
{
    if (need <= *cap) return;
    int nc = *cap ? *cap * 2 : 4;
    while (nc < need) nc *= 2;
    void* p = realloc(*a, nc * elemSize);
    if (p == NULL) exit(1);
    *a = p;
    *cap = nc;
}
```

调用时：`reserve((void**)&m->stations, &m->capStations, m->nstations + 1, sizeof(Station));`

线路的 `stations` 和 `minutes` 共用一个容量，不能对它们分别调用 `reserve`（第一次调用就把容量改掉了，第二次会以为不需要扩容）。可以单独写几行，两个数组一起 `realloc`。

</details>

### 4.3 逐行解析：先处理正确的文件

接下来是读取文件的主循环。这一步**先不管格式错误**，假设数据文件都是正确的，把建图的部分写对。错误检查放到 4.5 节再加。

用 `fgets` 每次读一行，行号加 1，再把这一行拆成几个部分。拆分可以用标准库的 `strtok`：分隔符设为 `" \t\r\n"`，这样空格、Tab、行末的换行符和 Windows 的 `\r` 一次都处理掉了。每一行最多取 3 个部分：

```c
char* tok = strtok(buf, " \t\r\n");             // 第一部分：LINE、END 或站名
char* arg = strtok(NULL, " \t\r\n");            // 第二部分：线路名或分钟数，可能没有
char* extra = arg ? strtok(NULL, " \t\r\n") : NULL;   // 第三部分：应该没有
```

`tok` 是 `NULL`（空行）或者以 `#` 开头（注释）时，跳过这一行。

解析时要记住「当前是否在某条线路中，是哪一条」，用一个变量 `cur` 就够了：`-1` 表示不在任何线路中，否则是正在读取的线路的编号。

- 遇到 `LINE`：新建线路，`cur` 设为它的编号；
- 遇到 `END`：`cur` 设为 -1；
- 其他的都是车站：调用 `getOrAddStation` 拿到编号，再调用 `appendStation`。

用 3.4 节那个小数据文件，看一遍每一行读进来以后，`stations`、邻接表、两个哈希表和 `lines` 是怎么一点点建起来的：

注意第 8 行的「乙 4」：乙在 A线 中已经出现过，`getOrAddStation` 直接返回编号 1，不会新建车站。所以乙的邻接表中，既有 A线 的两条边，又有 B线 的一条边，它就这样成了换乘站。程序中并没有专门「标记换乘站」的代码。

### 4.4 释放内存

`metroFree` 要释放所有 `malloc` 出来的东西：每个车站的名字和邻接表、每条线路的名字和两个数组、`stations` 和 `lines` 数组本身，以及两个哈希表。

**检查点 2**：运行 `tests/run.sh m1 build`，最后一行应该是：

```
build 这一组全部通过：9/9
```

这一组用的都是格式正确的数据文件，检查 `stats`、`line`、`station` 三个命令的输出，以及 Windows 换行符、Tab、缩进的注释。在 Linux 上，忘记释放内存也会让这一组失败。

### 4.5 检查格式错误

最后，按 2.2 节的表格和检查顺序，给每种情况加上检查。大部分检查都写在 4.3 节的三个分支里：

- 遇到 `LINE`：`cur` 不是 -1，说明上一条线路缺少 `END`；`arg` 为空、`extra` 不为空、线路名在 `lineIndex` 中已经存在，都是错误；
- 遇到 `END`：`cur` 是 -1，说明前面没有 `LINE`；这条线路少于 2 个车站也是错误；
- 车站：`cur` 是 -1，说明它不在任何线路中；然后检查分钟数，以及车站是否在这条线路中重复。

还有两个检查在循环之外：文件读完以后，如果 `cur` 不是 -1，说明最后一条线路缺少 `END`；如果一条线路都没有读到，也要报错。

在 4.3 节的演示中点「解析有错误的文件」，可以看到车站重复是怎么被发现的：第 4 行的「甲」已经在 `stationIndex` 中，`getOrAddStation` 返回编号 0，而 0 已经在 A线 的 `stations` 中了。

分钟数的检查不要用 `atoi`：`atoi("3分钟")` 返回 3，`atoi("abc")` 返回 0，都无法发现错误。自己逐个字符检查是不是数字，或者用 `strtol` 并检查它停下的位置。

<details>
<summary>提示：用 strtol 检查正整数</summary>

```c
char* end;
long v = strtol(arg, &end, 10);
if (*end != '\0' || v <= 0 || v > 100000) { /* 不是正整数 */ }
```

`end` 指向 `strtol` 停下的位置。如果整个字符串都是数字，`end` 指向结尾的 `'\0'`。不过 `strtol` 允许开头有空格和正负号，比如 `+3`，严格来说也应该算错误。参考实现选择了自己逐个字符检查。

</details>

<details>
<summary>提示：检查车站是否在线路中重复</summary>

在 `appendStation` 之前，遍历当前线路的 `stations` 数组，看这个编号是否已经存在。一条线路最多几十个车站，顺序查找就够了。

注意，要先调用 `getOrAddStation` 拿到编号再检查：同一个站名在一条线路中第二次出现时，它在 `stationIndex` 中已经存在，`getOrAddStation` 会返回同一个编号。

</details>

## 6. 常见错误

1. **扩容后还在使用旧的指针**。比如先写了 `Station* st = &m->stations[s];`，然后调用了 `getOrAddStation`，它可能 `realloc` 了 `stations` 数组，`st` 就指向了已经释放的内存。AddressSanitizer 会报告 `heap-use-after-free`。用编号代替指针，每次用的时候再取 `&m->stations[s]`，就不会有这个问题。这也是第 3.1 节用编号的另一个原因。
2. **哈希表只保存了键的指针**。读完文件后所有站名都变成了最后一行的内容。
3. **行末的 `\r` 没有去掉**。在 Windows 中编辑过的文件，`"果园\r"` 和 `"果园"` 是两个不同的站名，统计出的车站数量偏多。
4. **把 `nsegments` 加了两次**。每个区间在两个车站的邻接表中各有一条边，但区间只有一个。
5. **错误信息不完全一致**。全角的冒号「：」和括号「（）」写成了半角的，或者多了、少了空格。可以从文章中直接复制错误信息的格式。
6. **出错时没有释放内存**。正常读取的测试都通过了，`20-bad-*` 系列的测试却报告内存泄漏。

## 7. 思考题

1. 现在的 `station` 命令把相邻车站按线路分组输出。如果要输出「上一站」和「下一站」（比如 `1号线：上一站 动物园 3 分钟，下一站 市政府 2 分钟`），`Edge` 中需要增加什么信息？还是可以不修改结构，从 `Line` 中算出来？
2. 有些城市有**环线**，最后一站和首站之间也有一个区间。如果要支持环线，数据格式和 `appendStation` 要怎么改？`line` 命令的输出呢？
3. 如果两条线路共用一段轨道，比如 1 号线和 3 号线都直接从果园开到体育馆，邻接表中果园和体育馆之间会有两条边。这会不会影响后面的最短路径算法？

<details>
<summary>点击查看答案</summary>

1. 两种方法都可以。可以在 `Edge` 中增加一个方向的标记（比如 `int forward`，1 表示沿着线路的方向）；也可以不修改结构，在 `Line` 的 `stations` 数组中找到当前车站的位置 i，`i - 1` 就是上一站，`i + 1` 就是下一站。后者不增加冗余的数据，但每次都要在线路中查找一次，不过线路很短，代价可以忽略。

2. 可以在 `END` 后面增加一个可选的参数，比如 `END 3` 表示最后一站到首站还有一个 3 分钟的区间。处理 `END` 时，如果有这个参数，就在最后一站和首站之间再连一条边，`nsegments` 加 1。线路的数组中不需要再存一次首站，但 `line` 命令要把这一段也输出出来，比如在末尾加上 ` -3- 首站名`。另外，「线路至少要有 2 个车站」对环线应该改成至少 3 个：只有 2 个车站的环线，两站之间会有两条边。

3. 不影响正确性：两条边的权重分别是两条线路的运行时间，Dijkstra 会自动选择更短的那条，BFS 求站数时两条边的效果完全相同。但它们属于不同的线路，在里程碑 3 计算换乘时，「从 1 号线的果园坐到体育馆」和「从 3 号线的果园坐到体育馆」是两种不同的走法，到了体育馆以后在哪条线上，决定了接下来要不要换乘。这正是里程碑 3 要解决的问题。

</details>

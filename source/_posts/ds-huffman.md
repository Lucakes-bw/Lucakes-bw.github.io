> **本文目标**：理解变长编码和前缀编码；掌握哈夫曼树的构造方法（贪心）；会用小顶堆实现哈夫曼编码和解码；知道哈夫曼编码的压缩效果和局限。
>
> **前置知识**：《二叉树与遍历》、《堆与优先队列》。

## 1. 变长编码

计算机中，一个 ASCII 字符占 8 位。`abracadabra` 有 11 个字符，一共 88 位。但这 11 个字符中，`a` 出现了 5 次，`c` 和 `d` 各只出现 1 次。如果给 `a` 一个很短的编码，给 `c`、`d` 长一些的编码，总长度就可以缩短。这就是**变长编码**的思想，摩尔斯电码中最常用的字母 E 就只有一个点。

但变长编码有一个问题：怎样知道一个字符的编码在哪里结束？比如 `a = 0`、`b = 01`、`c = 1`，那么 `01` 是 `b` 还是 `ac`？解决方法是使用**前缀编码**：**任何一个字符的编码都不是另一个字符的编码的前缀**。这样从左到右读取时，一旦读到的位串和某个字符的编码相同，就可以确定是这个字符，不需要分隔符。

用一棵二叉树就能得到前缀编码：**字符都放在叶子上**，从根走到叶子，向左记 0，向右记 1。因为字符都在叶子上，从根到一个字符的路径不会经过另一个字符，所以没有编码是另一个编码的前缀。

问题变成了：怎样构造这棵树，让编码的总长度最短？

## 2. 哈夫曼算法

1952 年，还是研究生的 David Huffman 给出了答案：

1. 每个字符作为一棵只有一个节点的树，**权重**是它出现的次数；
2. 从所有的树中取出**权重最小的两棵**，作为左右子树合并成一棵新树，新树的权重是两者之和；
3. 重复第 2 步，直到只剩一棵树。

每次都选最小的两个，这是一种**贪心**策略：出现次数少的字符最早被合并，于是它们在树的最深处，编码最长；出现次数多的字符最后才被合并，离根最近，编码最短。可以证明，这样得到的编码总长度是所有前缀编码中最短的。

每次取出最小的两个、再放回一个，正是**小顶堆**擅长的操作：

```c
typedef struct HNode {
    unsigned char ch;
    long weight;                                // 出现次数
    struct HNode* left;
    struct HNode* right;
} HNode;

HNode* buildHuffman(const long freq[256])
{
    MinHeap heap = {.size = 0};
    for (int c = 0; c < 256; ++c) {
        if (freq[c] > 0) hpush(&heap, newNode((unsigned char)c, freq[c], NULL, NULL));
    }
    if (heap.size == 1) {                       // 只有一种字符：加一个虚拟节点，保证编码至少 1 位
        hpush(&heap, newNode(0, 0, NULL, NULL));
    }
    while (heap.size > 1) {
        HNode* a = hpop(&heap);                 // 权重最小的两棵树
        HNode* b = hpop(&heap);
        hpush(&heap, newNode(0, a->weight + b->weight, a, b));   // 合并成一棵
    }
    return heap.size ? hpop(&heap) : NULL;
}
```

`hpush` 和 `hpop` 是一个按 `weight` 排序的小顶堆，和上一篇的堆完全一样，只是元素是节点指针、比较的是权重（完整代码见文末）。n 种字符一共合并 n - 1 次，每次 O(log n)，总共 O(n log n)。

## 3. 编码和解码

建好树之后，从根出发走到每个叶子，记下路径，就得到了每个字符的编码：

```c
static void makeCodes(const HNode* n, char* buf, int depth, char codes[256][256])
{
    if (n->left == NULL && n->right == NULL) {
        buf[depth] = '\0';
        strcpy(codes[n->ch], buf);
        return;
    }
    buf[depth] = '0'; makeCodes(n->left, buf, depth + 1, codes);   // 左边是 0
    buf[depth] = '1'; makeCodes(n->right, buf, depth + 1, codes);  // 右边是 1
}
```

**解码**时从根出发，读到 0 往左走，读到 1 往右走，到达叶子就输出一个字符，然后回到根：

```c
const HNode* p = root;
for (const char* b = encoded; *b; ++b) {
    p = (*b == '0') ? p->left : p->right;
    if (p->left == NULL && p->right == NULL) {
        putchar(p->ch);
        p = root;
    }
}
```

对 `abracadabra`：

```
'a' 出现 5 次，编码 0
'b' 出现 2 次，编码 10
'c' 出现 1 次，编码 1110
'd' 出现 1 次，编码 1111
'r' 出现 2 次，编码 110
编码: 01011001110011110101100
共 23 位，原来 88 位（每个字符 8 位）
解码: abracadabra
```

88 位压缩到了 23 位。（演示中使用的是和这里完全相同的堆，所以得到的编码也完全相同。权重相同时选择哪一个，取决于堆的实现细节，不同的实现可能得到不同的编码，但总长度一定相同。）

实际的压缩文件中还要保存这棵树（或者每个字符的出现次数），解码的一方才能重建同样的树。对于很短的文本，这部分开销可能比节省的空间还多。

## 4. 实测：压缩真实的文件

把程序改为读取一个文件，按**字节**统计出现次数，计算编码后的大小（不包括保存树的开销）：

```c
FILE* f = fopen(argv[1], "rb");
if (f == NULL) { perror(argv[1]); return 1; }
long fq[256] = {0}, total = 0;
int ch;
while ((ch = fgetc(f)) != EOF) { fq[ch]++; total++; }
fclose(f);
HNode* r = buildHuffman(fq);
```

对本博客上一篇文章的 Markdown 源文件、本专栏的演示组件 `dsviz.js`，以及 10 万字节的随机数据（写作时的结果）：

```
ds-heap.md: 13767 字节，151 种不同的字节，编码后 10789 字节（78.4%），最长的编码 13 位，' ' 的编码 010，'e' 的编码 1101101
dsviz.js: 22782 字节，161 种不同的字节，编码后 15053 字节（66.1%），最长的编码 14 位，' ' 的编码 10，'e' 的编码 11110
rand.bin: 100000 字节，256 种不同的字节，编码后 100000 字节（100.0%），最长的编码 8 位
```

几个观察：

- JavaScript 代码中空格非常多，空格的编码只有 2 位，压缩到了 66%。
- 中文文章只压缩到 78%：中文字符在 UTF-8 中占 3 个字节，**按字节统计**时，这些字节的分布比英文字母均匀得多，能节省的空间就少。
- **随机数据完全无法压缩**：每个字节出现的次数几乎一样，最优的编码就是每个字节 8 位。这说明压缩的本质是利用数据中的**不均匀**和**重复**。

作为对比，用 `gzip` 压缩同一篇 Markdown 文件，只有 5902 字节（43%）。gzip 使用的 DEFLATE 算法先用 LZ77 找出**重复出现的字符串**，用「往前第几个位置、长度多少」代替，然后再对结果做哈夫曼编码。哈夫曼编码只看单个字节出现的频率，看不到「同一个单词在文中反复出现」这样的规律（比如被压缩的那篇文章中，「下沉」出现了 24 次，「堆顶」出现了 20 次）。实际的压缩格式（ZIP、PNG、JPEG、MP3）中，哈夫曼编码通常是最后一步。

程序用 `-fsanitize=address,undefined` 和 `leaks` 检查过。

## 5. 常见错误

1. **选择权重最小的两个时没有用堆，每次都排序或扫描**：O(n²)。
2. **只有一种字符时，编码长度是 0**：只有一个节点的树，根就是叶子，路径为空。要特殊处理，比如加一个虚拟节点。
3. **字符没有都放在叶子上**：得到的编码不是前缀编码，无法唯一解码。
4. **按 `char` 统计次数时用有符号的下标**：值大于 127 的字节（比如中文的 UTF-8 字节）变成负数，数组越界。要转换为 `unsigned char`。
5. **只比较编码后的位数，忘了保存编码表的开销**。

## 6. 小结

- 变长编码给出现多的字符短编码；前缀编码保证可以唯一解码
- 字符放在二叉树的叶子上，从根到叶子的路径（左 0 右 1）就是前缀编码
- 哈夫曼算法：每次合并权重最小的两棵树，用小顶堆实现，O(n log n)，得到最优的前缀编码
- 解码时从根出发，按位走到叶子
- 实测：代码文件压缩到 66%，中文文章 78%，随机数据无法压缩；gzip 结合了重复字符串的消除，效果更好

## 7. 练习

1. 手工构造 `mississippi` 的哈夫曼树，写出每个字符的编码和总位数。
2. 证明：在哈夫曼树中，没有只有一个孩子的节点。
3. 编码 `a = 0`、`b = 10`、`c = 110`、`d = 111` 是前缀编码吗？解码 `0110100111`。

<summary>点击查看答案</summary>

1. 次数：i 4，s 4，p 2，m 1。先合并 m(1) 和 p(2) 得到 3；再合并 3 和一个权重为 4 的字符（程序中的堆选择了 s）得到 7；最后合并剩下的 i(4) 和 7 得到 11。用本文的程序得到的结果：

   ```
   'i' 出现 4 次，编码 0
   'm' 出现 1 次，编码 100
   'p' 出现 2 次，编码 101
   's' 出现 4 次，编码 11
   共 21 位，原来 88 位（每个字符 8 位）
   ```

   如果第二步选择的是 i，i 和 s 的编码会互换，总位数仍然是 4×1 + 4×2 + 2×3 + 1×3 = 21 位。

2. 哈夫曼树中的每个内部节点都是由两棵树合并而来的，所以一定有两个孩子。这种每个内部节点都有两个孩子的二叉树叫**满二叉树**（这里的「满」和前面「每一层都满」的定义不同，不同的教材用法不一）。

3. 是前缀编码：0 不是其他编码的前缀，10 不是 110、111 的前缀。解码：`0` → a，`110` → c，`10` → b，`0` → a，`111` → d，结果是 `acbad`。

## 附：完整代码中的堆

```c
typedef struct { HNode* items[512]; int size; } MinHeap;

static void hswap(HNode** a, HNode** b) { HNode* t = *a; *a = *b; *b = t; }

static void hpush(MinHeap* h, HNode* n)
{
    int i = h->size++;
    h->items[i] = n;
    while (i > 0 && h->items[(i - 1) / 2]->weight > h->items[i]->weight) {
        hswap(&h->items[(i - 1) / 2], &h->items[i]);
        i = (i - 1) / 2;
    }
}

static HNode* hpop(MinHeap* h)
{
    HNode* top = h->items[0];
    h->items[0] = h->items[--h->size];
    int i = 0;
    for (;;) {
        int l = 2 * i + 1, r = l + 1, s = i;
        if (l < h->size && h->items[l]->weight < h->items[s]->weight) s = l;
        if (r < h->size && h->items[r]->weight < h->items[s]->weight) s = r;
        if (s == i) break;
        hswap(&h->items[i], &h->items[s]);
        i = s;
    }
    return top;
}
```

> **本文目标**：理解「先比较 A，A 相同再比较 B」这种多关键字的最短路径；知道 Dijkstra 对代价的要求是什么，为什么二元组满足这个要求；把里程碑 3 的代码改造成可以按两种代价运行。
>
> **前置知识**：需要先完成[里程碑 3](/posts/ds-project-metro-m3/)。

## 1. 要做什么

增加一个命令 `transfers <起点> <终点>`：找出**换乘次数最少**的路线；换乘次数相同的路线有好几条时，选**用时最短**的那一条。

```
metro> transfers 植物园 西站
植物园 → 西站：坐 11 站，换乘 1 次，用时 39 分钟（乘车 34 分钟，换乘 5 分钟）
  3号线：植物园 → 东湖，6 站，19 分钟
  4号线：东湖 → 西站，5 站，15 分钟
```

到这里，同一个问题已经有了三种答案：

| 命令 | 坐几站 | 换乘 | 用时 | 路线 |
|---|---|---|---|---|
| `stops 植物园 西站` | **6** | 3 次 | 32 分钟 | 3号线 → 1号线 → 2号线 → 4号线 |
| `fastest 植物园 西站` | 7 | 2 次 | **31** 分钟 | 3号线 → 2号线 → 4号线 |
| `transfers 植物园 西站` | 11 | **1** 次 | 39 分钟 | 3号线 → 4号线 |

三种都对，只是回答的问题不同。带着大件行李的人可能会选第三种：多坐 4 站、多花 8 分钟，换来少走两次换乘通道。

要实现的是 `route.c` 中的：

```c
int routeFewestTransfers(const Metro* m, int from, int to, Route* r);   // 返回值和 routeFastest 相同
```

## 2. 代价变成两个数

### 2.1 换乘次数相同时，还要比较时间

只求「换乘次数最少」并不难：把状态图中坐一站的边权重设为 0，换乘边权重设为 1，跑一遍 Dijkstra 就行了。但这样求出的只是一个次数，而一次换乘的走法往往有好几种。比如从人民广场到东湖，换乘一次的走法有 5 种：

```
1号线到东门，换 4号线        13 分钟
1号线到市政府，换 3号线       14 分钟
2号线到南湖，换 4号线         15 分钟
……                          22 分钟、26 分钟
```

只比较换乘次数，Dijkstra 会给出其中的任意一种，取决于堆中元素的顺序。我们要的是 13 分钟的那一种。

所以每个状态的代价要记**两个数**：（换乘次数，用时）。比较两个代价时，先比较换乘次数，次数少的更小；次数相同，再比较用时。这和字典中单词的排列顺序一样，叫作**字典序**。

| 边 | 代价的变化 |
|---|---|
| 坐一站 | （t，m）→（t，m + 区间分钟数） |
| 换乘 | （t，m）→（t + 1，m + `TRANSFER_MINUTES`） |

注意用时中仍然包括换乘的 5 分钟，这样最后得到的用时就是真实的用时。

### 2.2 为什么 Dijkstra 还能用

《最短路径》中说过，Dijkstra 遇到负权边会出错。它真正依赖的是两条性质：

1. **边的代价不是负的**：沿着一条边走，代价不会变小。这样，一个状态从堆中取出时，以后不可能再找到更小的代价到达它；
2. **加上同一个代价，大小关系不变**：如果 a ≤ b，那么 a + c ≤ b + c。这样，到达一个状态的最优走法，后面接上同样的路，仍然是最优的。

二元组按字典序比较、按分量相加，两条性质都满足：两个分量都不是负数；如果（t1，m1）≤（t2，m2），两边都加上（Δt，Δm），换乘次数的大小关系不变，次数相同时用时的大小关系也不变。所以 Dijkstra 完全不用改，只需要换一个「比较两个代价」的函数。

下面的演示用的是里程碑 3 中「两条线路共用一个区间」的数据：从甲到丙，坐 A线 一直到底要 12 分钟，不用换乘；在乙换 B线 只要 10 分钟，但要换乘一次。代价写成（换乘次数，用时）。点「时间最短」可以看到同一张图上按用时比较的结果。

<div class="dsviz" data-viz="metro-pair"></div>

两种比较方法中，（乙，B线）的代价都是（1，7）。按换乘比较时，它比（丙，A线）的（0，12）大，所以（丙，A线）先出堆，答案是不换乘；按时间比较时，7 比 12 小，它先出堆，接着走到（丙，B线），答案是 10 分钟。

### 2.3 能不能把换乘的权重设得很大

另一个常见的做法是只用一个数：换乘边的权重设成一个很大的数 BIG，比如 100000，代价 = 换乘次数 × BIG + 用时。只要 BIG 比任何一条路线的用时都大，「换乘少」就一定比「时间短」优先，效果和二元组相同。

这个方法能用，但要小心：

- BIG 要多大，取决于数据。示例城的路线最多几十分钟，而里程碑 2、3 用过的棋盘数据上，一条路线可以超过一千分钟。BIG 取小了，结果就会悄悄地错，而且只在大城市的数据上才会暴露；
- 取得太大，又可能溢出：换乘几十次，乘以一个很大的 BIG，就超过了 `int` 的范围。

二元组没有这两个问题，意思也更清楚，参考实现用的是二元组。

### 3.1 把 dist 换成二元组

把里程碑 3 中的 `int` 代价换成一个结构体，再写一个比较函数：

```c
typedef struct {
    int transfers;
    int minutes;
} Cost;

enum { BY_TIME, BY_TRANSFERS };

static int costLess(Cost a, Cost b, int mode)
{
    if (mode == BY_TRANSFERS && a.transfers != b.transfers) return a.transfers < b.transfers;
    return a.minutes < b.minutes;
}
```

`mode` 是 `BY_TIME` 时只比较用时，和里程碑 3 完全相同；是 `BY_TRANSFERS` 时先比较换乘次数。这样一份 Dijkstra 就能同时为两个函数服务：

```c
int routeFastest(const Metro* m, int from, int to, Route* r)
{
    return shortest(m, from, to, BY_TIME, r);
}

int routeFewestTransfers(const Metro* m, int from, int to, Route* r)
{
    return shortest(m, from, to, BY_TRANSFERS, r);
}
```

`shortest` 建立状态图、调用 `dijkstra`、还原路线，就是里程碑 3 中 `routeFastest` 的函数体。

要改的地方：

- `dist` 数组的类型从 `int*` 变成 `Cost*`，「无穷大」是 `{INT_MAX, INT_MAX}`；
- 堆的元素从（用时，状态）变成（代价，状态），堆中所有比较大小的地方都改成调用 `costLess`。堆需要知道当前的 `mode`，可以把它放在堆的结构体中；
- 坐一站：`{c.transfers, c.minutes + e->minutes}`；换乘：`{c.transfers + 1, c.minutes + TRANSFER_MINUTES}`；
- 松弛的条件从 `nc < dist[w]` 变成 `costLess(nc, dist[w], mode)`。

## 5. 常见错误

1. **只比较换乘次数**。换乘次数对了，但路线是随机的一条，`02-tie` 失败。
2. **换乘时忘了把次数加 1，或者坐一站时也加了 1**。前者等于只比较用时，`transfers` 的结果和 `fastest` 一样；后者比较的就变成了「站数 + 换乘次数」。
3. **改的时候把里程碑 3 改坏了**。比如在 `BY_TIME` 时也先比较了换乘次数，`fastest` 就变成了换乘最少。每改一步都运行一次全部测试。
4. **堆中的比较没有全部换成 `costLess`**。上浮用了新的比较、下沉还用旧的比较，堆的性质被破坏，结果时对时错。

## 6. 思考题

1. 如果只需要换乘**次数**，不关心时间，状态图上的边权重只有 0 和 1。这时有一种比 Dijkstra 更快的方法，叫 **0-1 BFS**：用一个双端队列，权重为 0 的边把新状态放到队头，权重为 1 的放到队尾。为什么这样做是对的？时间复杂度是多少？
2. 把三个目标综合起来：有的乘客认为「换乘一次相当于多坐 3 站」，有的认为「相当于多坐 10 分钟」。能不能让用户自己设置一个权重？代价还需要是二元组吗？
3. 如果要同时给出几条「各有所长」的路线，比如最快的、换乘最少的，以及介于两者之间的，应该怎么定义「介于两者之间」？

<details>
<summary>点击查看答案</summary>

1. Dijkstra 用堆，是为了每次取出代价最小的状态。当边的权重只有 0 和 1 时，可以证明双端队列中的状态，代价从队头到队尾是不减的，而且最多只有两种不同的值（d 和 d + 1）：0 边放到队头，它的代价和刚取出的相同，仍然是最小的；1 边放到队尾，代价是 d + 1，不会比队中任何一个小。所以双端队列的队头就是代价最小的状态，作用和堆一样，但每次操作是 O(1)。总的时间复杂度是 O(V + E)。

2. 可以。用户给出两个系数 α、β，代价 = 用时 + α × 换乘次数 + β × 站数，只是一个数，用里程碑 3 的 Dijkstra 就能求。不过显示给用户的用时仍然要按真实的规则计算。二元组适合「严格优先」的情况：无论多慢都先保证换乘少；加权适合「可以折算」的情况。

3. 一条路线如果在用时和换乘次数上都不比另一条差，并且至少有一项更好，就说它**支配**另一条。没有被任何路线支配的路线，组成**帕累托最优**集合，「介于两者之间」的就是这个集合中的其他路线。求帕累托集合可以把每个状态的 dist 从一个代价换成一组互不支配的代价，这叫多目标最短路径。地铁的换乘次数通常很少，每个状态最多保留几个代价，实际可行。

</details>
